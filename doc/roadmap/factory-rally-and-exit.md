# 生产建筑集结点与出口疏通计划

状态：用户于 2026-10-28 批准阶段 1，实测后要求修正过早编队及仍存在的堵门，继续实施阶段 2；两阶段及静态树石、四格到达修正已于同日获用户验收。当前行为见[集结规范](../spec/factory-rally.md)，下文保留阶段计划与当时的交付记录。

## 目标与范围

重工门口聚集单位时，新造车辆可能长期停在建筑内部，后续生产随之阻塞。本轮同时解决默认集结、出口堵塞和过早交接，最终效果是车辆正常驶出、生产继续、后续编队及 Skill 照常运行。

先交付盟军、苏军等当前规则中的地面车辆工厂，按工厂类别识别，不只写死某一种建筑 ID。兵营和船厂可以复用集结入口，但各自的出生和出口规则须单独核对，不据此承诺本轮自动疏通；机场与建筑生产队列不套用车辆出厂逻辑。

这是生产运行时的本机固定流程，不新增游戏 Skill，不让 DeepSeek 逐次判断堵门或生成疏通脚本。以下两个阶段分别交付，由用户验收阶段 1 后再继续阶段 2；批准本计划后先实施阶段 1。

## 已确认的实现依据

- 公开 `werhd.move([factoryId], x, y)` 经过正常的选中及移动动作链路；引擎对带集结点能力的生产建筑更新集结点，不移动建筑。本地源码已确认，接入时仍需实际对局验收。
- 当前公开单位视图没有集结点读回、工厂当前出厂单位 ID 或出口堵塞标记，不能把提交成功当成单位已经离厂。
- 桥已采集己方单位 ID、类型、格坐标、速度向量、闲置状态、模拟时间及生产队列，可连续观察“同一辆新车在重工内部长期不动”。不要求 `isIdle=true`，因为卡在寻路／出厂过程的单位可能并不闲置。
- 引擎按建筑占地计算车辆出生点、内部出口点和默认集结点；车辆从建筑中心出生，出厂的一段任务不可取消。新指令不保证能立刻替代这段任务，应优先处理真正挡路的单位。
- `observeProduction()` 目前按首次出现的 ID 累计产物；编队交接会提交 `stop`。需要保留真实产物计数，同时区分仍在出厂的成员，避免在出口阶段停车、拉队或重复生产。

## 阶段 1：接入集结点，减少出口堆积

### 交付行为

1. 支持“重工集结到三楼右下”“把这个重工的集结点设在这里”等指令，前者使用已绑定地图分区，后者只有上下文存在明确坐标时使用；没有位置依据时按附近合理位置执行并反馈。多个重工可明确指定或同时设置，不绑定到单一生产目标。
2. 首次接管车辆生产时，为尚无本系统设置记录的重工选择附近分散的默认集结位置；新建重工采用同一规则。默认位置初步选择在出口外约 4～8 格，避开已知建筑占地、出口通道和明显不可通行地形。多个工厂不集中到同一个门口。
3. 玩家明确设置优先于默认设置；本机记录设置来源、目标及提交结果，不每个采样窗口重发，不随新生产命令重置。公开 API 无法读回鼠标设置，因此不承诺自动识别或持续同步这类修改，也不周期覆盖它们。
4. 默认位置遇到实际停滞时允许有限换点；无法找到可靠候选时反馈原因，继续保留生产目标。选址只利用公开地形和己方对象信息，候选可用不等于已经证明引擎可寻路到达。

### 实现落点

- 在能力 Markdown 增加“生产建筑集结点”基础能力，与现有 `management.rally`（移动现有未编队单位）分开命名、绑定和解释。
- 桥动作新增明确的设置集结点语义，底层复用公开 `Move`；不靠放宽所有普通移动动作的对象范围接入。
- 建筑类型与工厂类别读取本局公开规则；占地和出口几何从对应游戏版本的规则、`art.ini` 及引擎出口规则提取最小数据，记录来源与版本，不把屏幕图片坐标当地图格坐标。缺少可靠几何的建筑不做大范围猜测。
- 每个建筑 ID 独立保存设置，同局重启不重复初始化；建筑被毁、出售或换局后清理。历史检查点没有这些字段时仍可加载。

### 验收

- 连续生产多辆坦克，新车离厂后前往集结位置，不在默认出口积成一团。
- 修改某座或全部重工的集结点，后续车辆使用新位置；新生产命令与 Companion 同局重启不会把它改回默认值。
- 两座重工分别设置，记录和动作互不串台。设置本身不改变已造单位的命令，不宣称能解除已经发生的堵塞。

## 阶段 2：检测堵门，疏通并衔接编队

### 检测与确认

1. 用建筑实际占地及出口区域关联新出现的车辆，跟踪其出生位置、最后有效位移和离厂进展。几何重叠、来源不清时不强行归到某一个工厂。
2. 同一车辆持续约 3 秒模拟时间仍停在出生／内部出口区域，且没有有效离厂进展，判为疑似出厂受阻；阈值由实机微调，正常开门和短暂等待不触发。游戏暂停、无新快照或 Companion 暂停期间不累加墙钟超时。
3. 队列进度及新产物变化作为辅助证据，不要求队列必须恰好显示 100%。区分出口占用与资金不足、低电、队列暂停；这些情况本身不触发疏散。
4. 允许发现接管前就已卡住的车，通过持续位置与出口占用确认，不能只依赖接管后的首次出生事件。

### 疏通过程

1. 先找出实际占据出口或紧邻通路的己方地面单位，优先疏散闲置单位，分配不同的附近让路点，避免只把堵塞移到另一格。
2. 对已有编队归属的可避让成员，经原控制对象统一安排短距离让路，每个单位保持一个最终动作来源；避让后依据最新任务继续。停止、暂停及后来的玩家命令优先，旧疏通动作立即失效，不恢复旧命令。采矿、维修、装卸等专用流程中的单位不从旁路硬抢控制权。
3. 中央新车处于不可取消的出厂流程时，先清出口并观察游戏恢复。车辆已可控制但仍不前进，再尝试有限的移出或更换集结点，不反复对中央车辆发送停车／移动。
4. 每次动作后等待新快照确认位移与出口释放，按工厂设置重试上限和冷却。没有可移动的己方阻挡者，或地形、敌方、盟友单位使出口无法解除时，显示实际受阻原因，不循环发令、不取消重造、不额外生产。

### 生产与交接

- 保留“已经生成”的真实产物 ID 和数量，另记“正在出厂／可交接”的事实；堵住的产物不被当成未生产，不补造替代车。
- 仍在出厂的车辆可以保留目标编队归属意图，但暂不发送停车交接、编队移动或 Skill 操作；已出厂的其他成员照常加入并行动，不拖住整批。
- 原方案只要求走出建筑；用户实测后明确修订为：坦克与步兵必须抵达出生时的集结点，才允许编入、补员、维修车组装、掩护或攻击。只走出建筑尚不放行；不同批次保留各自目标，后来修改建筑集结点只影响后来出生的成员。矿车保留原生采矿，不纳入等待。
- 取消生产仍按实际剩余队列撤销，已生成车辆保留，不因等待离厂重复取消或重发；全队战损判断将仍存活的出厂成员视为准备中，不提前终止任务。
- 同局恢复保留产物、集结设置和有效准备关系，重新采样堵塞证据与动作有效性；不重放历史让路指令，不把过期坐标直接当成当前障碍。

### 记录与验收

复用现有命令状态和 v3 对局记录，只保存“疑似堵塞／正在疏通／已恢复／仍受阻”等变化、相关建筑和单位 ID、动作结果及必要证据。无命令关联的人工生产阻塞记到当前对局，不伪造语音命令卡片；不新增截图、录屏或高频报告。

验收场景：

| 场景 | 预期 |
| --- | --- |
| 多个己方闲置单位堵住重工出口，中心已有卡住车辆 | 自动让路，中央车辆驶出，后续生产继续 |
| 正常开门／短暂停顿，或缺钱、低电、队列暂停 | 不误判成堵门，不无故疏散 |
| 连续造车并编队、补员、掩护或组装维修车 | 离厂前不被交接停车拉住，离厂后按原目标处理，数量准确 |
| 多重工、接管前堵塞、单位阵亡或建筑消失 | 按实际对象分别处理，不误关联、不继续操作失效对象 |
| 疏通过程中下达停止、取消、改令，随后同局重启 | 新命令优先；不重复生产、恢复旧任务或重放让路 |
| 出口被不可控制对象／不可通行地形堵死 | 有限尝试后显示原因，保留产物和目标，其他任务继续 |

## 验证与交付约定

自动检查复用生产、交接、归属与恢复测试，只补本轮具体故障：正常出厂不误报、持续卡住触发疏通、离厂前不停车交接、产量不重复、改令失效与同局恢复。同步能力及使用文档，执行 `capabilities:generate/check`、`typecheck`、`test`、`prompts:check` 和涉及的数据检查。

实际对局由用户操作、观看并验收，不自动发测试指令或采集画面。阶段 1 先确认公开 API 的实际效果与默认选点，再交付阶段 2 的堵门闭环。提交推送按用户指令执行。

## 阶段 1 交付

## 静态树石补丁与四格到达

用户进一步确认：本轮不考虑树木被摧毁，仅按冰天雪地原始地图做静态补丁，集结点周围 3×3 无障碍即可；到达范围放宽到四格。方案随后获准实施，已接通以下行为，待用户实机验收。

1. 离线读取当前冰天雪地原始地图的 `Terrain`、`OverlayPack` 及对应规则，导出树木、独立石块等阻挡对象的实际占用格到 `maps/ice/static-obstacles.json`。坐标沿用 `ra2-rxry`，保存地图与规则来源哈希；加载时核对地图来源，不把其他版本的障碍套进当前图。运行时只读生成的轻量数据，不要求玩家再持有原始资源，也不记录树木摧毁后的变化。
2. 初始选点、玩家设置、生产入队前复查、附近换点及出口让路选点共用同一个 3×3 静态障碍判定。中心及周围八格只要与树石占用格相交就排除，再沿用已有公开地形、建筑占地、地图有效范围和分区约束；临时单位驻留不作为永久障碍。首次加载补丁或同局恢复时，也先复查已有集结点一次，不能等下一次生产才处理存量卡住的成员。当前 (129,86) 附近的树 (130,85)、(130,87) 必须使旧点失效，不能靠放宽到达距离继续使用。
3. 新产物仍先记账，距离该产物有效集结点不超过四格、已经离开生产建筑及出口通道，并且空闲或短暂停稳后才交接。四格用于容纳游戏的靠近容差和分散落位，不用于放行仍在厂内或堵门的车；坦克、步兵共用此规则。旧点被本补丁判定占用时沿用现有换点流程，只迁移仍去旧点的未就绪成员，已就绪成员不召回。
4. 三次移动重试用尽后明确显示“集结受阻，重试已用尽”，不继续显示“准备有限重试”，也不因超时强行宣布到达。实际生产数量、已有产物、编队及 Skill 来源均保留，不重造。
