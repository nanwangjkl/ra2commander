# 掩护 Skill 开发计划

状态：2026-10-27 用户批准本计划并要求同时考虑掩护者更快和更慢。阶段 1 实测后，用户明确授权“下一阶段一起做”，本轮合并实现阶段 2、3及阶段 1 修正，整体交付后由用户验收。下文分阶段表保留原计划，实施边界以这次后续授权为准。

## 目标与使用方式

新增游戏 Skill `cover`，定义拟放入 `skills/cover/SKILL.md`。同一编队内部区分“被掩护成员”和“掩护成员”，整体接受移动、进攻、暂停和停止命令。两类成员都是该编队的真实成员；队内角色不创建额外编队或独立指挥脚本。

| 命令示例 | 预期行为 |
| --- | --- |
| 5 辆坦克组成 1 队，5 个警犬掩护 | 选择现有 5 辆坦克及 5 条狗，10 个成员都进入 1 队；坦克为被掩护成员，狗为掩护成员 |
| 给 1 队加 3 辆防空车掩护 | 选中现有防空车加入 1 队并承担掩护，原有掩护成员保留 |
| 1 队里的防空车负责掩护 | 调整队内现有成员的职责，其他成员作为被掩护成员，不新建队伍 |
| 1 队去三楼右下／1 队进攻 | 更换行动目标，保留队内角色与掩护要求 |
| 取消 1 队掩护 | 解除掩护安排，单位保留在 1 队，当前行动目标继续按普通编队处理 |
| 停止 1 队 | 全体成员停车，停止后续掩护和作战动作，不自行恢复 |

未说“生产／制造／新造”时使用现有单位；不足先用可用部分并反馈，沿用现有编入语义。明确新造时才组合已有生产能力，按实际产物及停车交接加入对应角色，不重复下单、不自动补员。同句中的掩护对象承接已经明确的编队，不要求玩家再说内部 ID。

首版覆盖地面移动单位组成的编队，包括坦克、步兵、警犬和地面防空单位；空中的敌人属于防空目标。飞行单位担任掩护、水陆混编和跨编队护送作为后续扩展，不在本轮交付中默认支持。

## 六项要求对应的行为

### 同一编队、一起行动

一个编队 ID、一份成员归属、一份当前行动目标。被掩护与掩护成员集合互斥，覆盖本次明确安排的成员。后来移动、攻击或替换脚本不会清掉掩护关系；重新安排掩护或明确取消时才更新。

角色与行进、站位事实独立于脚本局部记忆保存。新成员必须完成现有停车交接后才能接受动作；交接中的单位不提前算作已经就位。普通选队、成员数量和部队位置都以完整编队统计，侧栏补充两类成员数量。

### 最慢成员决定推进速度

公开规则提供基础 `speed`，公开单位提供位置、速度向量等事实，但没有整队限速设置。用户在0.2.0实测后明确采用预测跟随：最慢成员持续执行终点移动，其余按规则速度和公开方向追随前方预测点，实际位置只作纠偏。

- 引擎处理最慢成员的整段寻路，领行指令持续有效；其他成员沿游戏规则速度换算的前视点行军。
- 正常领先和小幅预测变化不停车、不掉头；只有严重脱队、转向或堵路时纠偏，接敌后再进入近身站位。
- 适用于两类成员：快狗、快防空车等慢坦克；若某种掩护单位实际更慢，则坦克等待掩护者。以本局 API 和实际位置为准，不按兵种名称猜速度。
- 受地形或寻路影响而掉队时，先局部重选落点并重聚，不因为其基础速度相同就忽略实际掉队。
- 慢速成员阵亡或转出后，重新计算基准；不继续等待失效 ID。

掩护编队的抵达与路线推进额外检查慢速成员及两类成员的队形关系，不能仅因全队 80% 到达就跳过仍在远处的慢速成员。到达范围保留必要宽度，不要求十个单位挤到一个点。

### 站在受护成员和最近敌人之间

以距离被掩护成员最近的当前可见敌人为威胁方向，在被掩护主体前方的短距离弧线上分散站位。多名掩护成员使用不同落点，必要时分别贴近邻近的被掩护成员；保留有效分工，避免每步互换位置。

站位方向和射击目标分别计算。防空单位即使正在打飞机，也继续遵守贴近受护队伍的站位要求。无可见敌人时沿行进方向贴近展开；原地待命时保持附近站位。敌人切换、从侧后方出现时调整方向，使用稳定阈值避免频繁绕队转圈。

初始建议参数为前出约 1～2 格、距最近受护成员约 2～4 格的有效掩护范围，按单位数量留出阵型宽度；参数在实机验收中调整，不先固化为通用授权限制。狭窄通道、悬崖或敌人贴脸导致无法站在理想位置时，优先保持近身与不脱队，再选择附近可达的屏障位置。

### 有条件跟打，不离队追击

普通掩护成员只协助被掩护成员当前明确攻击的敌人。先检查武器对该目标的适用性、真实射程以及是否仍处于掩护范围：

- 当前站位能攻击时开火；近战警犬不能为了凑近目标离开掩护范围。
- 射程不足、兵种不能攻击或目标失去可见性时，继续贴近和站位，正常等待；不报“非法射程”使整个脚本暂停。
- 敌人逃离射程或受护队伍继续移动时，撤掉掩护成员的旧追击动作，回到受护队伍附近。
- 不使用整组 `attackMove` 驱动掩护成员，以免由引擎自动追敌拉散队伍。
- 被掩护成员接敌推进同样经过队形协调，较快的受护成员不能借攻击命令绕过最慢成员约束。

当前公开单位类型没有自动索敌目标字段。以宿主记录的、确已提交给受护成员的攻击目标作为跟打依据；同队受护成员攻击多个目标时，按就近对应成员的有效目标分配。掩护模式中的攻击移动需要拆成可协调的推进和显式选敌，不能假装读取到引擎内部目标。只有引擎自主开火、没有可追踪目标时，掩护成员先保持站位。

基础速度不是实际瞬时速度，公开 API 也没有已确认的永久禁止追击开关。阶段 1 必须验证原生移动、停止、射程查询和自动索敌的实际行为；必要时在现有桥 tick 中为掩护成员做轻量距离复查，避免等待下一次完整快照才制止追击。能够承诺的是按控制周期维持队形并纠正偏离，不能承诺修改游戏引擎后的逐帧锁步或所有地形下绝对位于几何中点。

### 防空单位优先空中敌人

根据当前主副武器、载员状态及目标所在空／地层判断能力，不维护一张固定的防空单位名称表。桥补充公开 `zone`、离地状态等需要的事实并验证识别口径，不能只按 `ObjectType.Aircraft` 判断，以免漏掉飞行步兵。

选择顺序为：掩护范围内、当前站位可攻击的空中敌人 → 能攻击的受护成员当前目标 → 继续贴身待命。射程外的飞机不触发追击，也不阻塞受护队伍原任务。AA/AG、最小及最大射程和必要的武器适用性都依据当前对局真实规则；IFV 等状态改变后更新判断。

掩护选敌使用当前可见敌人，实际攻击遵守当前命令的对象和地域范围；区域清敌不因掩护变为全图清敌。这里的近身、射程和不追击条件直接来自本次 Skill 要求，只用于启用掩护的编队；普通攻击继续由游戏处理接近和开火。

## 执行架构

建议采用“Markdown Skill 定义 + 编队持续掩护配置 + 本机队内协同计算”。

1. `skills/cover/SKILL.md` 维护命令含义、成员角色、战术优先顺序及参数；现有 Skill 加载器补充第三种定义和运行类型，统一捕获版本与哈希。
2. 基础能力建议新增 `formation.cover` 与 `formation.uncover`，分别安排与解除队内掩护。`skill.run cover` 展开选人、编入和安排职责，使用共用单位选择器；参数支持队名、被掩护／掩护成员选择器、数量或 ID，以及明确新造的准备关联。
3. 编队继续持有当前移动、路线、守区或攻击目标及现有的一份脚本。脚本提出本次行动意图，掩护协调器统一形成该队最终移动、站位与开火动作。独立下令的双循环会造成抢指令，因此每个单位每步只有一个最终动作来源。
4. 协调器每步都维护有效行军意图和掩护位置，即使脚本本步因去重没有再次输出动作，也持续检查队形；后续改令替换行动意图，掩护配置保留。没有移动／攻击任务时就近保持掩护，不自行挑选远处任务。
5. 最终动作仍经过现有归属、对局、代次、地域及预算检查，立即响应停止和撤销。模型不参与逐 tick 站位、速度或射程决策；单纯安排现有成员掩护尽量只需一次理解请求。

建议新增的核心模块为 `packages/runtime/src/cover.ts`，能力绑定放 `apps/companion/src/capabilities/`；扩展桥契约、编队持续状态、编译视图与有限战术提示。避免把几何计算、距离跟随和进度分别再实现进模型提示词、脚本与宿主三处。实现时同步补充领域词汇和职责边界相关文档，不把本提案提前标为已采用的架构决策。

## 生命周期与异常规则

- 移动完成后，掩护关系继续存在；站位可以维持，卡片显示持续掩护。新移动／攻击继承关系，沿用现有 Skill“新任务就整体 superseded”的规则需要为 `cover` 单独区分。
- 暂停和停止对两类成员统一生效。取消掩护解除关系并撤销旧掩护动作，普通作战目标继续；不会拆队或恢复已经取消的旧任务。
- 转编和解散使旧掩护指令立即失效；转走成员不再被原队拉回。新编入成员未明确角色时按被掩护成员处理，不根据兵种偷偷改变职责。
- 掩护成员全部损失时，受护成员继续原任务并反馈掩护已损失，不自动补兵。被掩护成员全部损失时，剩余掩护成员就近集结并报告失去受护对象，等待玩家新命令。
- 卡路不能无期限拖住整队而不反馈：先有限次数局部重聚／换点，仍无法同路时显示队形受阻，保留成员归属，允许立即改令；不擅自忽略慢成员或跨越不可通行地形。
- 同局重启保存角色、Skill 版本、行进行为和必要分工；过期目标、位置和距离重新采样。持久化优先采用兼容的可选字段，无字段旧状态仍为普通编队。
- 侧栏与 v3 对局记录复用现有入口，补充角色人数、跟随／重聚／等待射程／掩护对空等事实；只记录变化，不反复存储几何候选，不新增全局轮询报告或额外截图。

## 分阶段实施与验收

| 阶段 | 交付 | 规模 | 用户验收重点 |
| --- | --- | --- | --- |
| 1：同队与协同行军 | API 核对、角色选择与单队归属、Skill 接线、最慢成员节奏、普通移动／路线、基本取消暂停停止与同局恢复 | 中偏大 | 5 坦克＋5 狗实际同属 1 队，移动时狗不独自冲走；更慢防空车加入时坦克也等待 |
| 2：完整掩护作战 | 威胁方向站位、显式攻击目标跟踪、近身跟打、不追击、动态防空优先，接入守区、区域清敌及进攻 | 大 | 队伍迎敌／转向时掩护成员靠前贴近；射程不足仍正常跟随；防空先打近处飞机 |
| 3：复杂场景收尾 | 明确新造后入队、动态成员、损失／堵路／改令、记录与恢复完整复核，参数微调 | 中 | 窄路和换向可用，转队不抢回，重启不重复生产，旧掩护动作不覆盖新命令 |

阶段 1 的 API 核对先完成：速度字段与地形差异、空地层、当前武器与射程查询、自动索敌追击及发令去重。若只能实现近似队形控制，先报告实测限制再选择可交付行为，不跳过验证假定存在原生限速或站桩开火接口。

阶段 2 至少覆盖：坦克＋狗对步兵与坦克；坦克＋防空车遭遇飞机；空中目标射程外与消失；敌人从侧后方接近；给正在掩护的队下达区域清敌和全队进攻。站位优先级是维持近身与整体行动，再争取威胁前侧的可达落点，最后选择不破坏队形的支援开火。

阶段 3 至少覆盖：追加掩护、显式新造、部分产出后先行加入、成员阵亡和转编、路口堵塞、取消掩护与停止全队的区别、移动与攻击之间切换及同局重启。后续阶段须在前一阶段用户验收后开始，不以自动检查代替实机验收。

自动检查只补充这些具体行为的关键用例，复用既有正常命令链路；运行 `typecheck`、`test`、`prompts:check`、`capabilities:generate/check` 及相关数据检查。实机由用户自行观看，不自动截图、录屏、添加测试提示或移动镜头。每阶段交付说明改动与实际限制，提交推送按用户指令执行。

## 本次批准的范围

原批准从阶段 1 开始，后续授权已允许合并完成阶段 2、3；不重写普通作战系统、不扩大到其他地图或接入真实语音。掩护配置和动作整理仅对启用该 Skill 的编队生效，本轮完成后统一验收。

## 阶段 1 交付（2026-10-27，待用户验收）

- `cover@0.1.0`、`formation.cover/uncover` 接通现有成员的同队组织与角色安排；配置待实际停车交接后生效，后续普通移动及有序路线继承角色。单独调用可走本机流程，同句既有脚本编队请求合并为一个目标。
- 行军以全体成员真实进展计算领先等待和恢复；公开基础速度用于慢成员识别与抵达检查，缺少速度时结合实际位置继续。规则查询按兵种缓存在 tick 采样回调外；本机规则中灰熊 MTNK=7、履带防空车 HTK=8、IFV=10，实际对局仍以公开 API 为准。
- 普通移动与路线用本机动作协调；已有脚本移动被安排掩护后同样进行队形协调，保留目标和进度。取消角色不拆队，后续新普通命令恢复原入口。暂停、停止与恢复统一处理两类成员。
- v4 检查点可选字段保存角色、Skill 来源和行军事实，兼容旧无掩护状态。v3 对局记录保存必要的速度、角色和等待变化，不新增画面采集。
- 9 项新增关键检查覆盖快掩护、慢掩护、同速、同句十人编队、路线与重启、暂停取消及普通入口边界、桥速度缓存与角色修改不干扰全局生产编译；共 184 项离线测试及类型、提示词和 30 项能力接线检查通过。实机由用户验收，不自动向游戏发测试动作。
- 已重连用户新开的对局，只读确认本局 API 有效速度与 `inRange/weaponVs` 入口。实际速度会经过游戏换算，不能直接使用 ini 的 Speed 标号判断跨兵种快慢；真实移动、停走观感与寻路由用户验收。

本阶段不声称已交付迎敌屏障、支援射击与防空优先。公开 API 的射程和自动索敌边界在后续作战阶段继续结合实机确认，普通攻击的射程处理保持原行为。

阶段 1 验收反馈修正：一局“造5辆坦克，编入1队，2个IFV掩护1队”在缺少现有 IFV 时，被绑定重决策改成仅生产 IFV，实际没有启用掩护。先禁止丢失职责的替换；用户随后批准后续阶段合并实现，继续接通下述生产来源和完整作战，无需玩家拆成生产、安排角色两句话。

## 合并交付（cover@0.2.0，待整体验收）

- 明确生产后按有限目标及真实产物接入角色，复用本句已有生产，支持首批交接后行动和剩余成员继续加入；不提前结束尚有准备的路线，不吸收无关同型单位，不重放生产。
- 掩护队移动、巡逻、守区和进攻统一由本机形成最终动作，快慢双方都受实际队形节奏约束；迎敌近身站位、当前射程内支援、空中优先及偏离后回靠共用该入口。普通未启用掩护的攻击保留原处理。
- 当前武器射程查询按64对批次置于tick外，最终开火前再确认，不向射程外目标发起追击。只读取公开信息，游戏自动索敌且没有公开目标的攻击不猜测跟打。
- 取消区分掩护自身准备与独立生产；转队后不抢回，解散不因独立生产重建旧队；角色、来源、交接及行军事实兼容 v4 恢复，v3 归档只保存必要变化。
- 短距离站位受阻时先回靠实际成员位置，多次无进展提示队形受阻；采样之间的偏移、狭窄地形与转向观感仍须玩家实机验收，不承诺引擎级锁步。

## 0.2.1 行军体验修正

用户反馈停走磕绊后，明确要求使用游戏设定速度预测跟随。本轮改为最慢成员直接向终点移动，其余成员追随滚动前视点，正常行军不再用stop控制节奏。`rules().speed`按256内部单位/格换算，公开velocity仅用于地面方向，不用自测速度；转弯暂时停止时保留已知航向，改令、规则变化或领行失效后重算。向量和预测事实沿用现有对局记录与v4恢复，不增加画面采集。

本轮通过194项离线测试及类型、提示词、能力检查。五坦克两IFV的无障碍行军检查中，最慢成员同一终点只发令一次，正常行军没有停车指令；两种速度差和同速都能抵达。真实地形、拥堵和转向观感仍待用户实机验收。
