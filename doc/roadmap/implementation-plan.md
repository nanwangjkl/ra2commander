# 实施与验证计划

本项目基于 [ra2web](https://github.com/ra2web/ra2web.github.io) 设计独立的本机语音指挥伴随程序。

状态：M1 与 M2 单队循环已实施并实测（见[API 调查的原型实测记录](../architecture/game-api.md)），M3 的编队、生产与持久化已部分实施，M4 未开始。更新日期：2026-10-18。行为依据为[产品需求](../spec/requirements.md)，模块边界见[架构设计](../architecture/overview.md)。

2026-10-21 [编队与全局脚本统一替换方案](script-ownership-refactor.md)已批准并实施，29 项自动化检查及两队与全局的实机验收通过；下文保留既有阶段和历史验证记录，新任务粒度以 ADR 006 为准。

同日补验发现并修正生成脚本把区域中心误作明确移动终点的问题。两队分别到达指定位置、编译中停止和移动中停止已在同局验证，详见[指定终点与停止补验](script-ownership-refactor.md#指定终点与停止补验2026-10-21)。

同日完成[六句模拟语音实机测试](voice-six-commands.md)：新增文字转写解析入口、展开基地、生产后编队、显式地名绑定和持续补电目标。五项通过，第五项卫星建成但建设过程曾缺电，记为部分达标；攻击阶段对手未建设基地，不能替代复杂对抗验证。

2026-10-23 新增[浏览器工作台、命令侧栏与语音输入开发计划](browser-workbench-and-voice.md)，当前待用户批准。该项拆为四阶段，每阶段须由用户验收通过后才继续；它补充本路线图的界面与语音工作，尚未开始实现。

## 首版范围

| 项目 | 首版范围 |
| --- | --- |
| 程序形态 | 独立开源的本机伴随程序，管理专用游戏窗口 |
| 平台与地图 | macOS、冰天雪地 |
| 操作方式 | 按键说话、松开提交；巡视镜头与语音下令 |
| 模型 | 本地语音识别优先；云端模型可切换 |
| 验证规模 | 100 个地面战斗单位、8 个编队与已授权生产并行 |
| 验收目标 | 命令符合度、部队调动与执行效率；bot 提供对抗环境 |

## 实施阶段

先用少量坦克、一个编队完成端到端验证，再扩展到冰天雪地、100 个地面战斗单位、8 个编队与生产并行。文本输入可用于早期调试命令编译器，最终交互使用语音。

| 阶段 | 交付物 | 验证依据 |
| --- | --- | --- |
| M1 公共 API 桥 | 专用 Chromium、固定桥、快照与动作批次、会话代次和效果观察 | 实际游戏加载成功，桥回调不被停用，旧会话动作被拒绝 |
| M2 单队完整循环 | Agent 组件评估、语音识别、对象绑定、新 JS、校验与修复、本机持续执行；校准地域 | 完成候选组件保留或替换结论，守区、原地射击、战损条件、停止和普通改令符合需求 |
| M3 并行与生产 | 多编队调度、制造前置、优先级、故障修复和断网处理 | 云端等待不阻塞已有任务，无擅自生产或抢兵；队列限制可反馈 |
| M4 规模与 Skill | 100 单位/8 编队报告、群体 API 命令对比、首批经确认 Skill | 报告执行效率、延迟、识别问题和追击偏移，据实测确定性能门槛 |

## 首个原型与组件评估

M1 获得公共快照和动作桥后，在 M2 前半段用少量坦克、一个编队验证[命令编译与本机执行循环](../architecture/overview.md#模块与数据流)。先通过调试文本验证编译、执行、停止和改令，再接入本地语音识别；最终玩家交互仍为语音指挥与巡视。

| 验证项 | 原型交付物 | 检查内容 |
| --- | --- | --- |
| 模型接入 | Pi 模型接口候选适配器、请求与取消记录 | 使用至少两种计划支持的云端模型验证切换、流式输出和错误处理；已取消命令的迟到结果不能激活任务 |
| 命令编译 | Agent Core 候选、查询与校验工具、每控制对象当前 JS 及版本记录（早期原型为每命令独立脚本） | 能生成脚本、收到校验错误后修复，在有限重试内结束；保持原目标与授权 |
| 单队运行 | 专用任务运行时、快照驱动脚本、动作检查和效果记录 | 少量坦克完成移动、守桥和条件回撤；普通改令就绪后切换，停止命令立即撤权 |
| 两个循环独立运行 | 云生成等待、请求取消、断网和脚本故障样本 | 云模型等待或断网时旧任务继续；故障任务按规则暂停，修复不产生新战略许可；其他健康任务继续运行在 M3 验证 |

条件回撤使用已唯一绑定的桥口和维修地点验证：“战损超过六成”按原始成员阵亡比例计算，10 辆坦克阵亡 6 辆不触发、7 辆触发。实际追击与路径效果通过真实游戏观察，回放用于检查生成动作及授权条件。

组件评估记录候选版本、样本、生成成功率、修复次数、各阶段延迟和接入成本。达到原型行为要求且便于控制工具、取消与模型切换时保留 Pi 候选；若 Agent Core 接入成本过高，可保留成熟模型适配组件，用轻量 TypeScript 流程组织生成与校验。编译工作流需要更复杂的状态编排时再评估 LangGraph。

单队链路通过后，再推进 M3 的多编队与生产、M4 的 100 单位/8 编队规模及 Skill。候选组件尚未成为正式依赖，框架能力和脚本语法通过均不能代替实际微操效果验证。

## 组件评估结论（2026-10-06，M2 后）

按"首个原型与组件评估"要求，对 Pi 模型适配库与 Agent Core 的评估结论：**暂缓引入，保留自研轻量层**。

| 评估判据 | 自研层（~100 行）实测 | Pi 候选增量 |
| --- | --- | --- |
| 多模型切换 | DeepSeek/GLM 实测切换；`MODEL_<NAME>_*` 泛化配置接入任意 OpenAI 兼容服务 | 非 OpenAI 兼容协议供应商 |
| 取消 | AbortSignal 全链路；迟到结果不激活待实测 | 多轮工具调用中途取消 |
| 生成质量/延迟 | 端到端 3-7s（关思考+压缩输出），质量过校验与真实执行 | 相当 |
| 接入成本 | 零依赖 | 迁移+重新验证编译链路 |

重新评估触发信号：接入 ≥4 家且协议差异超出 OpenAI 兼容范围；语音交互需要流式生成反馈；修复循环演化为复杂多轮编排（届时按架构文档先评估 LangGraph）。

## 执行边界加固（2026-10-18）

已实现：停止与暂停后的旧结果丢弃、改令及修复请求取消、对局 UUID 与源快照检查、宿主默认拒绝的动作授权、跨步/修复/重启的生产额度、严格战损阈值，以及独立进程 QuickJS 的时间/内存/栈/输出限制。CLI 改用显式地域与条件参数，旧 v1 授权状态不自动恢复；操作方式见 [AGENTS.md](../../AGENTS.md)。这些策略仍可随原型体验调整。

本轮验证使用真实隔离执行器、合成快照和页面桥模拟环境，没有重跑真实对局。新边界下的攻击射程、原生偏移纠正、建筑落地及并行开销仍需真实游戏复验，不将自动化检查等同于 M3 全部验收。

2026-10-21 调整测试范围：`pnpm test` 保留正常命令冒烟、关键竞态与状态故障、基础隔离和地图数据检查；移除实验性授权策略、精确阈值、固定地图统计及大批资源边界组合的断言。本次只调整测试与说明，不修改运行逻辑。后续优先通过真实对局发现问题，再为具体故障补回归。

## 验证方法

语法与类型检查发现接口错误，快照回放验证脚本输出和授权符合度；实际对局验证原生追击、路径、建筑落地、桥面/地面和并行开销。回放不代替引擎效果测试，bot 胜负不代替执行正确性。

对比基线采用相同玩家任务和初始条件下的普通 API 群体命令，也由程序下令。记录地图资源版本、MOD、起点、单位构成与随机性，多次场景报告分布，不把直线距离当作已知最优可达路径。

## 指标

| 指标 | 测量内容 |
| --- | --- |
| 新命令响应 | 语音结束→识别完成→理解/代码生成→校验就绪→首次有效动作，分别记录 P50/P95 |
| 持续微操延迟 | 快照 tick→本机计算→浏览器提交，记录过期批次丢弃率 |
| 集结效率 | 固定起终点的完成时间、到达比例、队形离散和实际轨迹 |
| 接战效率 | 可见合法目标前的无效等待、交火参与代理指标和重选目标及时性 |
| 发令效率 | 重复订单、每单位发令量、频繁改令的实际影响 |
| 权限符合度 | 无授权撤退、出击、追击、补员或建设；条件触发正确率 |
| 原生偏移 | 追击偏移距离、发现时刻、纠正提交时刻与观察到的恢复时刻 |
| 并行性 | 语音、云模型和某个故障脚本是否阻塞其他编队或生产 |
| 资源成本 | 游戏同时运行时的 CPU、内存、冷启动与云请求成本 |

公开 API 没有完整发射/命中事件，不能精确归因每辆坦克的伤害贡献。代理指标须注明计算方法和限制；提交成功与观察到动作效果分开记录。

兵力规模已确认，延迟、纠正距离和效率门槛尚待实测。技术选型和模型大小同样以真实游戏同时运行的数据评估，不提前宣称达到性能目标。

## 关键场景

| 场景 | 应验证的结果 |
| --- | --- |
| 10 辆坦克守桥，战损超过六成回撤 | 6 辆阵亡不触发，7 辆触发；受伤与补员不改变口径 |
| 区外射程内目标离开射程或视野 | 停止或纠正原生追击，记录偏移；不扩大授权 |
| 普通改令与“停止” | 前者就绪后切换，后者先撤权；迟到云回答不能恢复旧任务 |
| 新造单位、重叠成员与转编 | 未授权不补员，含糊冲突澄清，明确转编不被旧任务抢回 |
| 缺电、矿车损失与非法前置 | 报告阻塞，不追加战略目标，制造闭包只包含必要前置 |
| 同类与异类生产优先级 | 正确处理整类暂停和未提交顺序，不自动取消已投入项目 |
| 死亡、部署和形态转换 | 成员与战损基准正确，不把正常转换当阵亡 |
| 路径阻塞、桥面与维修停靠 | 观察实际效果与阻塞，修完不追加未经授权任务 |
| 云断网、脚本超时或异常 | 已有健康任务继续，修复不改变目标或权限 |
| 离局、页面桥失联和恢复 | 旧会话动作失效，跨局状态不复用，恢复前重新观测 |
| 巡视模式与游戏原生输入 | 保留镜头与录音，单位指令入口确实被屏蔽 |

## Skill 入库与待验证事实

候选 Skill 说明参数、版本、所需 API、适用范围和已知限制，提供代表性回放与实际场景验证；开发者审阅确认后发布，运行时只加载已登记版本。共享代码与每局状态隔离，原命令权限持续生效。

下一步需验证实际地图版本与边界、游戏加载和输入过滤、桥接持续开销、生成算法有效性、中文识别和规模性能。具体依赖版本、包装方式、重试限额、执行资源限制与性能门槛在原型中确定；这些是工程验证项，不是新的产品行为授权。
