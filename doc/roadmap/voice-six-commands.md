# 六句模拟语音实机测试

日期：2026-10-21。环境：游戏快照 `7f6858a`、gonghui MOD、冰天雪地、French、初始10000资金；模型为 DeepSeek `deepseek-flash`。用户开启新对局，初始仅有基地车。

将六句原话依次交给 `say`，作为语音识别后的转写文字。模型先输出结构化操作，宿主绑定阵营名称、编队、地图分区和生产前置，再由模型生成全局或编队脚本。真实录音识别未参与本轮测试。

## 本轮结果

| 原话 | 结果 | 观察依据 |
| --- | --- | --- |
| 展开基地 | 通过 | AMCV转换为GACNST，观察到建造厂出现 |
| 制造战车工厂 | 修正后通过 | 电厂→矿场/兵营→战车工厂全部实际落地 |
| 制造5辆坦克并编入1队 | 通过 | 本生产目标累计产出5个新MTNK身份，全部归属1队 |
| 1队去三楼右下 | 通过 | 目的地候选格152,83，5辆实际位置均查询到目标分区 |
| 制造间谍卫星，保持电量健康 | 部分达标 | 科技前置和卫星建成，最终电力600/335；建设途中曾200/235缺电，未做到全程健康 |
| 摧毁全部敌人 | 通过 | 1队主动接近并摧毁可见敌方基地车；末次公开状态敌方`defeated=true`，游戏进入结算页；5辆坦克存活 |

本轮对手未建设基地，卫星揭图后只观察到一辆敌方基地车，不能据此评价复杂对抗和微操效率。各步记录的时间包含模型等待、人工检查和续测，不作为性能指标。

过程包含两次解析修正：工厂阵营已能由本局建造厂确定，目录需按阵营提供；模型返回的卫星显示名需唯一映射到原生名称。两处修正后从原步骤继续，未重复已完成的生产。结算验收另修正了败北玩家`combatant=false`导致遗漏的判断，依据已保存的同局败北快照和结算画面确认结果。

持续补电目前能在出现需求后补足，但建设与电厂的队列安排仍可能造成短暂缺电。本轮将其保留为部分达标，不以最终电力充足覆盖过程中的违例。

## 重跑

测试定义：`tests/scenarios/voice-six-commands.json`。执行器：`apps/companion/tools/run-voice-scenario.mjs`。

```sh
pnpm companion
pnpm scenario:voice          # 需先在游戏中新开只有基地车的盟军冰天雪地对局
pnpm scenario:voice --resume # 仅续测同局，已完成步骤和已激活目标不重放
```

2026-10-22 按用户要求移除了测试提示、自动跟随镜头、定时截图和报告/录像生成。用户自行观看游戏，执行器只下达指令、读取状态并在终端反馈进度。`.runtime/voice-six/progress.json` 仅保存续测所需的步骤、指令响应和末次败北状态；旧版 `result.json` 可用于迁移续测进度。原话、解析和目标仍记录在 `.runtime/transcripts/`。这些运行时数据不纳入版本库。

自动化新增4项基本接入检查：转写名称绑定及目标合并、实际展开确认、新产物编队、持续补电不重复下单。它们不证明建设过程始终有电，实机部分达标的结果单独保留。
