# 进攻时自动碾压开发计划

状态：2026-10-30 已完成三步交付。用户实测反馈碾压可以工作，随后授权修复剩余车辆停车和敌方名称绑定，并要求统一提交推送。实现口径见[自动碾压](../spec/crushing.md)。

## 目标与范围

玩家沿用“1队进攻”“攻击敌方步兵”等命令，由宿主选择开火或碾压，不增加一次 DeepSeek 决策，也不要求另建编队或单独调用 Skill。

| 项目 | 本轮口径 |
| --- | --- |
| 执行单位 | 仅灰熊 `MTNK`、犀牛 `HTNK`、苏军防空履带车 `HTK` |
| 主动碾压目标 | 当前命令允许攻击的可见敌方步兵，静态规则 `Crushable=true`，且处于可接触的地面层 |
| 排除目标 | 警犬 `ADOG`、`DOG`；空中目标；明确不可被碾压的步兵；不在原命令范围内的敌人 |
| 其他单位／目标 | 沿用现有火力进攻，包括 IFV、天启及攻击建筑、载具、幻影坦克 |
| 多车多目标 | 优先分配不同敌人，避免所有车辆追同一个步兵 |

排除狗指不把狗选为主动碾压目标。原生移动碰撞仍可能碾过途经或同格的其他单位，公开接口不能为某个兵种单独设置碾压免疫。

## API 核对结果

[公共类型快照](../../packages/contracts/src/werhd-api.d.ts)明确区分 `Move=0`、`ForceMove=1`、`ForceAttack=3`。本机发布实现也将 ForceMove 的强制标志传入移动任务。

碾压使用以下公开入口：

```js
werhd.order([tankId], {
  type: werhd.OrderType.ForceMove,
  target: {
    x: enemy.tile.rx,
    y: enemy.tile.ry,
    onBridge: enemy.onBridge === true,
  },
})
```

ForceMove 属于地格指令；当前公开 `order` 不接受给它传 `{objectId}`，也没有单独的 `forceMove()` 或 `crush()` 方法。因此必须保存敌人 ID，由宿主根据当前公开位置刷新强移落点，不能依赖一条原生追踪单位指令。

强移仍遵守游戏地形、通行和实际碰撞规则，提交成功不证明已经碾压。当前 `rules()` 不返回 `Crusher/Crushable`，采用与现有目录同源的规则导入；对局规则覆盖后无法通过公开 API 读回的差异，交由实际执行观察及受阻处理，不猜测成功。

## 第一步：补齐规则与碾压原语

- 扩展现有目录导入，批量保存 `crusher`、`crushable`，按引擎规则处理缺省值：步兵默认可被碾压，其他类型默认不可；执行能力默认关闭。生成数据保留来源哈希，旧目录缺字段时沿用普通攻击。
- 在 `prompts/games/current-mod.md` 配置执行单位名单及狗的排除名单。规则能力与本次启用范围分别维护，升星或其他车辆拥有碾压能力也不自动扩大这三类名单。
- 快照补齐公开的 `onBridge`，结合现有 `zone`、位置与高度识别地面／空中及桥面层。不能完整识别的特殊姿态仍由游戏判定，不把静态标记当作必定可碾压。
- 新增宿主内部 `crush` 动作，携带己方单位和敌人 ID；最终桥复查当前成员、目标资格与原攻击范围，再转换为上面的 ForceMove。模型继续提交现有攻击意图，普通移动、出厂集结与采矿不使用该原语。

涉及入口：`packages/command/src/game-data.ts`、游戏目录与 Markdown、`packages/contracts/`、`packages/game-werhd/`。

## 第二步：作战分配与持续追踪

统一在宿主作战层处理，覆盖普通编队、直接选择单位攻击、区域攻击、守卫／基地防守，以及旧脚本提出的兼容攻击请求。先应用原命令的目标、地域和成员要求，再为本轮进攻的可碾压目标分配车辆；攻击建筑或指定其他兵种不会被改成追步兵。

分配规则：

1. 保留仍有效的车—敌人配对，减少每帧互换目标和掉头。
2. 其余车辆按就近成本分配尚未占用的敌人；目标够用时一车一目标。同一命令涉及多个编队时共享当前占用，不各自重复选同一人。
3. 同格同桥面有多名步兵时按同一个接触点协调，优先一辆车处理；目标不足时剩余车辆保留队形或攻击其他非碾压目标，避免挤向同一点。
4. 配对成员发强移，不并发对该目标的普通攻击；其他成员继续自己的火力任务。
5. 目标移动到其他格时节流更新落点；目标未动时保持原指令，不每个快照重发，不用反复停车维持追踪。
6. 目标消失、离开防区、变为空中或失去资格时释放配对，结束旧强移，再选当前合法目标；消失只表示失去观察，不记为已碾死。

掩护仍使用现有协同器：

- 远距离推进保留最慢成员领行和预测跟随，进入队形允许的接敌范围后再分头碾压。
- 担任掩护的 HTK 保留对空优先，只分配近身范围内的碾压落点；执行中按控制周期复查，目标逃远或成员偏离时结束追赶并回靠，不宣称能锁定每帧距离或预知完整路径。
- 主体不同目标的分派也受当前队形约束，不能让更快的 HTK 借碾压先行脱队；受约束成员继续协同接近，暂不炮击其可碾压目标。

配对、最近落点、重试及回退状态保存在目标事实中，与现有命令、归属和动作记录共同恢复。暂停、停止、取消、改令、转编、阵亡、全灭、对局结束均释放失效占用；同局重启先复查当前目标，不盲目重放旧坐标。只提交经当前快照和控制对象版本复查的动作。

涉及入口：建议新增 `packages/runtime/src/crushing.ts`，接入 `attack-orders.ts`、`cover-combat.ts`、守卫／防守和统一动作提交处；不另建一套指挥脚本。

## 第三步：受阻处理、归档与验收

正常情况优先碾压，不同时炮击已配对的步兵。持续无位移、同一落点反复无法接近时，先有限调整接近点或改派其他合适车辆，不把正常绕路或移动中的目标算成卡死。

建议用户批阅的回退口径：有限尝试后仍无法执行时，暂时对该车—目标改用普通火力，并显示“碾压受阻，改用火力”，避免长期空转。回退不能下一帧立即清零重试；目标确实改变接触条件或玩家新下指令后再尝试。这是正常“碾压代替炮击”的受阻例外。

复用现有命令卡片及 v3 对局记录，补充“正在碾压／调整接近／受阻改用火力”和配对、目标位置、实际提交结果等变化，不新增截图、录屏、报告页面或高频重复观察。不凭提交、到格或敌人消失宣称击杀归因。

| 验收场景 | 预期 |
| --- | --- |
| 灰熊、犀牛、HTK 进攻普通可碾压步兵 | 发 ForceMove，正常情况下不发该车对该步兵的 Attack |
| 多车进攻分散步兵／一格多名步兵 | 分头处理不同目标，避免集中挤一个点 |
| 狗、磁爆步兵等排除项；IFV、天启作为攻击者 | 保留普通攻击 |
| 目标移动、离区、飞起或失去观察 | 更新合法落点或结束追踪，不沿旧坐标继续冲 |
| 桥上／桥下单位 | 使用正确桥面目标；强移不等于无视桥面和地形 |
| 混编及掩护队，HTK 比坦克更快，并有空中敌人 | 不脱队，掩护 HTK 对空优先，近身碾压受队形约束 |
| 到点前生产成员、暂停／停止／取消、新命令和同局恢复 | 保留现有交接与控制生命周期，不被迟到动作恢复旧追击 |
| 碾压确实受阻 | 有限调整后按获批口径回退，其他单位继续行动 |

自动验证只覆盖上述具体行为及正常攻击链路，运行类型、提示词、目录和能力检查；使用离线回放，不调用云模型或操作真实对局。真实碾压效果及队形流畅度由用户观看验收。
