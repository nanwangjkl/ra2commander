# 用同一份玩家能力定义连接提示、校验与宿主

终端已有的编队和管理能力曾未接入自然语言，独立维护的提示列表、操作类型与绑定分支也会出现遗漏。玩家提出基础操作、游戏规则与战术约定、常规操作 Skill 三层，并要求提示保存为 Markdown。按已批准的分期方案，A 外置固定提示，B 统一能力入口；C、D 分别继续拆分规则战术与实现 Skill。

玩家能力以 Markdown 声明名称、版本、参数、选择方式、绑定器和反馈。模型说明、输入校验与生成的 TS 类型读取同一份定义；宿主绑定器继续实现实际单位、编队、地图和目标选择。参数契约与已生成类型不一致、绑定器缺失或实现没有声明入口时，检查明确报错。接受一个小型结构化元信息约定和类型生成步骤，以减少多份协议相互偏离；暂不引入通用插件或任意可执行配置。

终端语法保留为适配器，与侧栏及自然语言共用分派。生产与组织能力转换为现有全局目标，作战能力转换为编队目标；停止、暂停及可直接恢复的操作由宿主立即处理。命令理解仍一次模型请求，按控制对象生成完整脚本，不为三层内容分别请求模型。

本次同时明确 Skill 指可复用的常规行动定义，由基础能力组合，可附示例代码；此点扩展 [004](004-new-command-scripts-and-cross-battle-skills.md) 中只复用代码的表述。Skill 的运行实例、依赖与探索能力尚未实现，不借此批准进入 D。每队/全局独立脚本、AI 生成微操、玩家决定目标与跨局状态隔离继续沿用。

参数与说明的一致性由结构化定义、类型生成和接线检查维护；这些检查不能替代模型理解质量或实际游戏验收。普通攻击仍交给游戏处理接近与开火，基础能力目录不恢复射程拒绝规则。
