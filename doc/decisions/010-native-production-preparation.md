# 生产的规则准备独立于代码生成

用户批准[生产协调本机化计划](../roadmap/production-native-execution.md)后，新生产由本机静态处理器按已有计划发令；真实规则准备独立于脚本编译，并按目标检查取消和更新。生产台账、预留、队列、集结交接及放置继续共用，不建立另一套生产状态。这样能省去转发代码的生成等待，同时保留脚本与本机目标共存；代价是固定实现的错误由开发修正，不能交给模型重写宿主代码。

本决策局部修订 [ADR 006](006-script-per-control-owner.md) 的全局生产脚本职责。全局与编队仍是控制对象，共享调度、动作提交及暂停语义；原有全局脚本不因新增本机生产而替换。新旧来源的共享前置、队列和待建耗电以实际目标及提交事实计算，不依赖一次编译恰好包含哪些目标。

用户于 2026-10-31 明确要求继续第二阶段，持续补电和显式队列控制同样本机执行。供需按全局实际提交统一预测；队列继续使用既有归属表，仅增加持久化的提交票据，以区分意图、正回执和实际状态。承担 API 缺少动作身份的限制：未知暂停不猜测归属，不盲目重发。

旧无标记目标不自动迁移，提供按能力回退，保留同一目标身份、生产台账和产物。直接取消生产与 Skill 取消继续采用各自原有语义。本轮实现已于 2026-10-31 通过用户实机验收；行为说明见[生产执行方式](../spec/production-execution.md)。
