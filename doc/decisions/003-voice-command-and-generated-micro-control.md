# 玩家只发语音命令，AI 编写全部微操

2026-10-22 修订：本记录中“歧义通过语音澄清”的默认规则由 [ADR 007](007-action-first-command-interpretation.md) 替代。AI 优先按当前战况作合理选择并执行，玩家通过后续命令纠正。

本项目基于 [ra2web](https://github.com/ra2web/ra2web.github.io) 设计独立的本机语音指挥伴随程序。

## 背景

玩家希望发出“坦克集群接战”这样的指挥命令，具体攻击哪些敌军、每辆车分配什么目标、如何站位和何时行动由电脑执行。让玩家枚举敌人或手动接管单位，会把微操负担重新交回玩家。

同时，项目要求 AI 编写微操算法。仅让模型从固定手写战术库挑选技能，不能满足这一目标；每次动作都等待云端回答又会让实时控制受到网络和生成延迟影响。

## 决策

玩家对局内只巡视和发语音命令，不通过选中单位、键鼠指令或接管按钮直接操作部队。首版使用按键说话，录音按键仅控制语音输入。

云模型为命令编写执行逻辑，本机脚本负责持续的观察—动作闭环。AI 负责选敌、火力、站位、队形与时机；宿主提供几何与底层动作能力，管理权限、资源和生命周期。

## 备选方案与取舍

| 方案 | 优点 | 未采用或采用的理由 |
| --- | --- | --- |
| 模型选择固定手写战术技能 | 行为较容易预先验证 | 不能满足 AI 编写完整微操的要求 |
| 云模型逐次决定每辆车的动作 | 决策直接使用模型上下文 | 实时循环依赖云端等待，难以保证编队与生产持续并行 |
| AI 生成代码，本机持续执行 | 生成算法可动态观察状态，持续循环无须等待每次云回答 | 采用；承担生成代码质量与执行效果验证成本 |

## 影响

编队与地点必须能通过兵种、角色、地域和名称绑定。界面显示匹配、任务、阻塞与结果，歧义通过语音澄清；保留镜头巡视，验证原生单位输入被屏蔽。

Skill 可以复用经确认的微操代码，但不能用固定手写战术决策器替代模型生成的微操。宿主检查权限不意味着宿主负责另行选择敌人或战术。

语法通过并不代表微操有效。验收评价调动、交火和并行效率；冰天雪地 bot 是对抗环境，胜负受到玩家战略影响，不作为系统正确性的判据。

## 验证依据

验证玩家只用语音能建立编队并下达接战任务，代码自行绑定可见目标并持续执行。云模型等待和语音识别期间，已有编队及生产继续；镜头操作不会下达单位命令。对比相同条件的普通 API 群体命令，报告生成微操的实际效果。
