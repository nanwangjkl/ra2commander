# 每编队与全局各一份脚本，统一整体替换

每条生产命令各建任务会增加队列、前置建设和状态协调；为主脚本另做增量修改机制也会产生两套生命周期。现改为每个编队独立一份脚本，全局管理共用一份脚本，两类共用完整生成、校验、切换与修复流程。所有编队平级。

玩家命令新增、修改或取消任务目标，生成对应控制对象的新代码版本。任务目标、归属与执行事实独立保存，整体替换代码时清空局部记忆，保留生产进度和其他未取消目标。普通改令就绪后切换，停止与取消立即生效。

全局脚本提出生产、建设与成员管理动作，编队脚本指挥本队行动。转编先使旧归属结果失效，完成停车提交后开放接收队指挥。全局故障影响全部全局管理，各编队仍独立运行；这是集中协调带来的取舍。

本决策替代 [ADR 004](004-new-command-scripts-and-cross-battle-skills.md) 中“每命令新任务实例”的粒度要求，其跨局 Skill 与状态隔离原则继续保留。开发范围与验收见[改造方案](../roadmap/script-ownership-refactor.md)。

## 2026-10-27：固定建筑操作由本机执行

按用户批准的[运行时整理阶段 5A](../roadmap/runtime-simplification.md)，新增建筑维修、出售目标直接复用宿主已有的固定步骤，省去模型生成转发代码。全局与编队仍是控制对象；脚本只接收归自己执行的目标，每个目标只有一个动作来源。两种来源共用调度、暂停、取消、动作预算、即时校验和提交台账。本机目标增改不替换无关代码或局部记忆，脚本版本只随实际代码替换递增。

这是对上文“所有目标均需生成脚本”的局部修订：保留模型对玩家意图的理解和战术脚本生成，固定流程避免额外延迟和生成错误；代价是固定实现的故障须由开发者修正。此类错误记入对局与侧栏，不请求模型重写宿主实现；脚本仍使用限次修复。默认情况下旧状态无执行方式标识时继续走脚本，不在恢复时迁移。关闭试点开关时，未结束的本机建筑目标保留同一身份与事实，改由脚本准备后接管。5A 已于 2026-10-27 由用户验收，批准提交推送后开始 5B；采矿和搬迁仍须经 5B 验收，其他目标未迁移。

## 2026-10-27：扩展到采矿与基地搬迁

用户验收 5A 并批准 5B 后，将新采矿与搬迁目标接入同一本机执行路径。已编队采矿仍属于该编队，生效时撤销旧目标及迟到候选；后续战术脚本生效时也撤销旧采矿，保证一个队只有当前任务的动作来源。全局新增固定目标保留无关脚本与记忆；搬迁后的建造继续由原生产脚本执行，依赖真实搬迁完成。

执行方式与既有进度继续按 v4 保存。每项能力有独立回退开关，同一目标和事实交给脚本接管，不迁移默认无标记旧目标、不清空对局；搬迁等待接管时继续跟踪真实变形。5B 已于 2026-10-27 由用户验收，生产、探路、维修车和作战未扩大迁移。

## 2026-10-27：同队掩护的持续配置与行军协调

用户批准[掩护计划](../roadmap/cover-skill.md)并追加授权合并后续阶段后，队内角色作为编队持续配置保存，不建立额外护卫编队或脚本。现有成员和有限生产产物在停车交接后获得角色；掩护队的移动、守区和进攻由同一本机协调器按真实位置形成最终动作，沿用该控制对象的预算、即时校验、暂停和撤权。角色与有限来源不随移动目标或脚本替换丢失。

全部行军节奏只写进提示词会依赖每轮生成代码正确执行；宿主集中协调能让两种速度差采用同一规则，代价是这部分策略与故障由本机实现承担。引擎没有整队限速入口；按用户追加要求，最慢成员持续执行原生终点移动，其余成员按规则速度和公开方向追随前视点，不以日常停走维持队形。位置反馈处理转向、严重脱队及堵路，接敌后处理近身站位。规则速度按引擎单位换算，不从位移计时推定。当前武器查询置于tick采样外，最终掩护开火在桥确认射程，避免模型或原生攻击移动驱使掩护成员脱队追击。

既有地面作战脚本获得掩护配置后也由同一协调计算动作，不并行运行另一个指挥者。取消掩护保留当前任务，后续新普通命令恢复原入口。掩护内的对空自卫只扩展掩护成员的近身防御，不扩大受护成员的攻击对象或地域。普通未启用掩护的攻击不增加射程拒绝条件；合并实现后待玩家整体验收。

2026-10-30：用户批准将新有限生产迁到本机执行，规则准备与代码生成解耦；该部分职责由 [ADR 010](010-native-production-preparation.md) 修订，持续补电、显式队列控制及旧目标保留原路径。
