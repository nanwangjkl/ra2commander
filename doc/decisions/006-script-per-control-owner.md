# 每编队与全局独立替换脚本

每条生产命令各建脚本会增加队列与前置协调，为永不替换的主脚本另做增量机制也会产生两套生命周期。因此选择每编队与全局各一个控制对象，全部编队平级；需要脚本的目标在对象内合编，共用生成、校验、切换与修复流程。

目标、归属和执行事实独立保存，整体换代码只清空局部记忆，保留生产和未取消目标。普通改令候选就绪后切换，停止取消立即生效；转编在实际停车提交成功后交接。全局脚本故障影响集中管理，各编队仍独立，这属于集中协调的代价。

本决策替代 [ADR 004](004-new-command-scripts-and-cross-battle-skills.md) 的每命令脚本粒度，跨局状态隔离与 Skill 复用继续保留。

## 后续修订

2026-10-27 起，固定建筑、采矿与搬迁等目标改由本机处理，省去转发代码生成。固定目标与脚本共用控制对象、预算、归属、提交及取消，单个目标只接受一个动作来源；本机目标增改不替换无关脚本。代价是固定实现故障由开发修正，模型不能重写宿主；旧无标记目标继续脚本，回退保留身份与事实。

同队掩护的角色与预测行军由本机统一协调，避免各轮生成不同快慢策略。引擎无整队限速，最慢主体持续领行，其余按真实规则速度预测跟随；维护该策略与故障的成本由宿主承担，不另建护卫控制对象。

2026-10-30～31：[ADR 010](010-native-production-preparation.md) 进一步将生产准备、有限生产、补电和队列控制从生成代码解耦。后续固定流程迁移不改变本决策的控制对象和独立事实边界，结果见[开发里程碑](../roadmap/development-history.md)。
