# 快速反应优先，命令按合理解释执行

## 背景

RTS 中玩家需要迅速看到命令产生行动。此前为了准确绑定对象而要求消除歧义，曾发生“无法确定盟军重工还是苏军重工，因此不执行”的情况。玩家明确接受执行错误，愿意通过下一条命令补救；下令后不动的代价高于一次合理误判。

## 决策

只要能形成合理的行动解释，就结合当前可见战况选择并执行。多个阵营项目、同类对象或战术方案不构成默认拒绝或等待确认的理由。简短反馈实际选择，由玩家的后续命令修正。

“造重工”优先选择现在可造的同类项目，再参考当前阵营和已有设施；仍有多个候选就选一个。“展开基地”遇到多辆基地车时选择一辆执行。选敌、站位和顺序允许近似，随战况反馈调整，不等待最优解。部分目标缺少对象时先执行其余可执行部分，并说明具体未执行项。

本记录替代 [ADR 001](001-player-owns-strategic-decisions.md) 和 [ADR 003](003-voice-command-and-generated-micro-control.md) 中“歧义默认先澄清”的规则。玩家继续决定任务目标，Agent 负责补全目标内的执行选择。

## 备选方案与取舍

| 方案 | 取舍 |
| --- | --- |
| 唯一绑定后才执行 | 降低误解，但会因普通歧义停滞，不采用 |
| 按合理解释先执行 | 采用；提高反应速度，接受误选、浪费资源和次优行动，由玩家纠正 |

## 影响与验证

提示词和对象绑定均不能再把“多个候选”当作空操作的理由。不为普通歧义增加确认轮次或第二次模型询问。旧任务在新脚本准备期间继续，停止和取消立即阻止后续动作。

没有实际对象、能力尚未接入或接口失败仍需如实反馈，不能用“已执行”掩盖未行动。原型先落地生产名称和基地车选择，以及多操作的独立对象绑定；完整自然语言纠错和其他对象解析随命令能力继续扩展。

验证同名重工与阵营误选都能形成有效生产请求，多辆基地车不会阻止展开，单个无法绑定的操作不阻止同句其他有效目标。验收优先看首个有效动作的等待与无动作情况，再看准确性和效果。
