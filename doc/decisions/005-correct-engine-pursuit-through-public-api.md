# 通过监控纠正处理游戏原生追击

2026-10-24 修订：按玩家批准的 [008](008-command-actions-and-engine-attack.md)，普通攻击移除宿主和页面桥的射程前置拦截，由游戏处理接近与开火。下文保留早期守区取舍的历史背景；明确的守区边界监控仍适用。

本项目基于 [ra2web](https://github.com/ra2web/ra2web.github.io) 设计独立的本机语音指挥伴随程序。

## 背景

玩家要求没有明确命令不得追击。游戏普通攻击却可能在目标离开射程或视线后自动追逐，守卫指令也可能有限追逐；公共 API 没有禁止追击开关，项目又不能修改游戏代码。

因此，脚本只给当前射程内目标下攻击命令，也无法证明引擎后续完全不产生追击位移。这是公共接口的行为缺口，不是可以单靠提示词解决的问题。

## 决策

首版持续监控目标、单位位置和授权地域，通过可用的停止或纠正动作处理原生追击。玩家接受短暂引擎偏移，要求记录偏移距离与纠正时间；具体门槛在实际对局测量后确定。

脚本主动越权追击仍然是错误。引擎偏移不改变命令权限，也不能作为继续出击或追击的理由。首版不承诺严格零追击位移。

## 备选方案与取舍

| 方案 | 优点 | 未采用或采用的理由 |
| --- | --- | --- |
| 只在目标当前处于射程内时下攻击 | 实现简单，减少明显主动追敌 | 后续引擎仍可能追逐，不能维持约束 |
| 修改引擎或新增禁止追击参数 | 有机会在引擎层保证行为 | 超出仅用现有 API 的项目边界 |
| 持续监控、纠正并测量 | 保持独立接入，纠正效果可观察 | 采用；承担检测、通信和动作生效之间的短暂偏移 |

## 影响

实时监控不能依赖正在生成的新云回答，应在本机持续执行。目标离开射程、进入迷雾或偏移扩大时及时停止或纠正，同时避免无意义的重复订单；发令频率对交火的实际影响需测量。

守区内可原地射击区外目标，区内站位调整不产生离区出击许可。移动路径与到达后的守区分别授权，不能把正常赶路或地域绕行错误视为追击。

监控周期、桥接与游戏订单生效都有延迟，失联时也不能保证撤回已接收动作。报告应区分脚本主动违规与引擎偏移，分别记录，不能只统计最终是否回到守区。

## 验证依据

用目标撤离射程、消失于迷雾和离开守区的实际场景观察轨迹。记录偏移开始、检测、纠正提交和恢复时刻，以及最大偏移距离；验证脚本没有主动扩展追击范围。快照回放只能验证输出，完整引擎场景才证明纠正效果。

接口依据见[API 调查](../architecture/game-api.md)，度量与失联场景见[实施与验证计划](../roadmap/implementation-plan.md)。
