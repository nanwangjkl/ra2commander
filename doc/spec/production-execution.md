# 生产执行方式

本页描述[生产协调本机化计划](../roadmap/production-native-execution.md)两阶段的实现。用户于 2026-10-31 明确授权继续阶段2，随后实机验收通过并要求提交推送。

## 当前范围

默认的新生产目标由本机执行，包括普通单位与建筑、持续补电、显式队列暂停及探路犬、维修车组件和掩护的有限生产。自然语言、直接能力与终端共用入口，生产方式在公共目标入口确定，各 Skill 不维护独立生产台账。

仅包含本机能力的生产命令保留一次命令理解、零代码生成；直接能力不调用模型。无标记旧目标及显式回退保留脚本。编队移动、攻击等后续能力按自身执行方式处理，混合命令仍可能按需生成代码。

## 准备与发令

本机生产在激活前复用 `prepareGoals` 读取实际科技树、生产设施、目标类型、队列类型与耗电；规则查询与代码生成分离，同次命令共享规则请求，但每个目标独立等待和失败。其他已就绪本机能力先激活，规则准备不占普通绑定队列，也不使已有全局脚本失效。

准备请求捕获命令的提示词和目录版本。提交准备结果前复查目标身份、目标要求、对局与取消信号；改量、暂停、取消或换局使对应迟到结果失效。新增目标准备失败显示错误；修改目标准备失败时旧生效要求及已有进度保留，其他目标继续。

`goals/production.ts` 从同一目标的 `productionPlan` 与约束提出就绪建筑放置、产物交接及当前可造项目的生产请求。放置、队列裁剪、生产前集结点检查、预留检查点、真实提交和回执继续由公共入口执行；没有第二套完成标记或生产计数器。

## 数量与共享事实

本次有限数量只累计该目标的真实新产物，不用已有同名对象抵扣，也不因阵亡自动补造。多目标共用必要前置、队列空位与就绪建筑；同名目标沿用现有串行确认规则，未决回执或不能确认来源时不盲目重发。

修改数量保留已提交和已观察产物。减少只收紧后续下单，不自动撤销已入队数量；增加要求准备期间，即使原批次刚好完成也不能结束新增要求。明确取消生产仍按[生产取消](production-cancellation.md)撤销目标剩余队列；Skill 取消和全局停止保持原边界。

持续补电按当前实际电量，加上所有已提交建筑的待建耗电，减去所有待建电厂的供电，计算剩余缺口；本机、旧脚本、明确新增电厂及不同供电量的电厂共用此事实。来源捕获的规则优先，共享前置提前归账给尚未准备的目标时复用其他已准备来源。未决提交同样保留，不重复补同一缺口；已建成的供电只通过实际电量计入一次。满足余量后持续待命，耗电增加或电厂损失后再补足。

补电提交与同名明确新造电厂可归账到后者，保留其数量、位置和搬迁依赖；有限目标仍按自己的新增数量完成，不被已有电厂抵消。不同名称的未提交建设计划不当作已经产生的供电，不为了等待将来的电厂而停住当前可执行补电。旧脚本及其记忆不因新事实被替换。

独立准备允许已就绪目标先执行；同轮均已就绪时按绑定顺序发令，不按规则查询返回顺序重排。原建设目标取消后，其他目标仍需要、且尚未发起撤销的共享电厂前置保留并可由补电继续放置；明确取消的目标建筑仍按原撤销规则处理。

坦克和步兵依然先抵达出生时的集结点，再完成停车交接；矿车保留原生采矿。建筑方位、异形分区、间距与搬迁完成依赖不变。暂时无落点或集结点受阻时保留事实、继续其他可执行目标。

## 显式队列控制

只有玩家明确给出 `queues` 时才暂停相应忙队列。队列必须可观察；本目标仍需要的前置队列及自身产物队列不暂停。玩家原已暂停或其他目标拥有的暂停不认领、不恢复。实际生产已结束后即恢复自身暂停，不等待单位集结或编队；最后的完成状态须等恢复确认。全局暂停保留事实并暂停新调度，取消和停止继续清理自身已暂停队列。

意图先保存到目标可选的 `queueControl.orders`，既有 `pausedQueues` 仍是唯一暂停归属。正暂停回执才建立归属，公开暂停状态确认后关闭票据；其他队列恰好完工则按公开状态释放，不反复暂停已就绪建筑。恢复回执不等于已经恢复，须等队列公开状态不再暂停才清除归属。取消时迟到的暂停正回执仍会进入收尾。空回执或明确未提交可重试，API 错误即使返回零提交也保留未知票据，不盲目重发。未知暂停不能仅凭队列已暂停认作自己的，需保留待确认说明，不能替玩家恢复。

## 恢复与回退

运行状态仍为 v4，沿用目标、生产记录、真实产物、队列归属和交接数据。准备失败原因与队列意图是可选字段，不把进程内准备请求作为已生效目标保存。同局重启保留已激活目标；未完成的新要求重新准备规则，未确认的队列意图保守恢复，不重放已提交生产及队列操作。队列暂不可观察时保留票据；对局结束不继续发队列动作。无标记旧目标恢复后继续脚本。

`RA2C_PRODUCTION_EXECUTOR=script pnpm companion` 将新生产交给脚本，也可使尚未结束的本机生产保留同一目标、台账和队列归属，等待脚本接管。旧脚本仍经公共提交确认队列操作，宿主保证恢复自身队列的收尾。探索、维修和其他能力的回退开关独立，不因生产回退而重建其任务或清空对局。

离线检查覆盖真实规则准备、共享查询、分批生产、原生集结交接、混合及重复补电、迟到准备失效、改量与暂停、取消期间的队列回执、未决意图恢复及脚本回退；模型调用使用替身检查，不访问云模型或游戏。
