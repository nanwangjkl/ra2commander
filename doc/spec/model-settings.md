# 本机模型设置

2026-11-02 已实现并获用户验收，对应[阶段 1 开发方案](../roadmap/history-download-and-model-settings.md)。用户明确只保留 URL、Key、模型名称三个字段，支持更换不同模型，但不保存多套配置。

## 使用与生效

填写 URL、API Key 和模型名称，点击“保存”。URL 为 Base URL，不带末尾 `/chat/completions`，客户端自动补接；支持 HTTP(S)，不接受地址中的认证、查询参数或片段。页面保留“保存”和“测试连接”按钮，不提供模型服务下拉、配置名称、来源说明、Key 清除或重新加载按钮。

已有 Key 不回显，留空表示保留，填写新值表示替换；更换 URL 时必须提供适用于新地址的 Key。保存直接覆盖当前唯一配置，不建立配置列表或保留旧模型配置。

保存成功后，后续新请求取新 provider 实例，已发出的模型请求继续使用原实例；不取消在途指令、不重编已运行脚本、不刷新游戏。保存本身不发送云模型请求。“测试连接”用当前表单发起最小模型请求，成功或失败均不保存配置、不切换实际使用的模型、不执行游戏动作；请求关闭或 Companion 退出会中止测试，最长约十五秒。模型名称与 URL 没有固定候选名单，使用兼容协议的不同模型均可通过改填这三个字段接入。

切换到设置页会读取当前配置，保留未保存的字段草稿；发生并发修改时，过时保存会明确失败，切换页签重新读取后可再次保存。Companion 重连保留草稿，迟到响应不能覆盖新挂载。

## 文件与兼容

配置由 Node 宿主保存到 `.runtime/settings.json`，格式版本为 2，仅包含修订号和一个 `configuration={baseUrl,model,apiKey}`。使用同步提交、临时文件原子替换及落盘同步；成功写盘后才替换内存中的 provider。写入失败保留旧配置，输入留在表单供重试。

没有本机配置时，继续兼容既有 `MODEL_<NAME>_*`、`DEEPSEEK_*` 和 `GLM_*` 环境配置，按原默认顺序取第一套可用配置。页面保存后该唯一配置优先，不改写 `.env`、不将其他环境模型保存为配置列表。

读取此前版本 1 的多配置文件时，只保留当时明确选中的配置并原子转换为版本 2，删除其余配置项；当前模型的 URL、Key 与模型名保留。终端调试用 provider 集合最多包含 `current` 一项，不再另行保存选择状态。

文件以 `0600` 模式新建，随 `.runtime/` 忽略，不入 Git 或对局导出包；这是本机文件保存，不是加密存储。页面只获得 URL、模型名、是否已有 Key 和修订号，Key 不回显。模型选择归档只记录非敏感字段，已知 Key 在错误回显中脱敏。后续打包阶段再适配平台凭据存储和用户数据目录。

无效或无法转换的配置文件保留原样，工作台显示错误；修复该文件并重启后可恢复编辑。缺少 Key 时明确报错，不悄悄切换到另一个模型。

## 接口与代码入口

- `GET /commander/settings`：当前唯一配置的非敏感视图。
- `POST /commander/settings`：覆盖当前配置，携带当前 `revision`。
- `POST /commander/settings/test`：测试当前表单，不保存。
- 写接口复用同源检查和请求体大小限制；保存不额外触发连接测试或游戏动作。

宿主配置在 `apps/companion/src/model-settings.ts`，接口在 `workbench-api.ts`，表单在 `ui/model-settings-panel.ts`；新理解、绑定修正和编译请求记录当前配置的非敏感信息与修订号，认证请求头不归档。
