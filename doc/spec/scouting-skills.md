# 探路 Skill 与探索事实

阶段 D 探路流程已于 2026-10-26 获用户认可，当前按逐区 60% 微调并复核对局记录。首个游戏 Skill 是 `scout`，定义位于 [`skills/scout/SKILL.md`](../../skills/scout/SKILL.md)。它与开发 Agent 使用的 Codex Skill 无关。

## 玩家入口

| 命令 | 行为 |
| --- | --- |
| 探路 | 优先使用现有未编队侦察犬（默认最多三条），没有时才新造，建立独立侦察队 |
| 用五条狗探路 | 本次固定生产五条，其余流程相同 |
| 用已有狗探路 | 默认选三条现有侦察犬；优先未编队，不足按可用成员继续，不追加生产 |
| 取消探路 | 取消最近一次活动探路的后续步骤及未完成目标 |
| 让某队探索三楼右下 | `map.explore` 使用指定现有编队探索该分区，不新增生产 |

也可使用共用终端入口：

```text
cap skill.run {"skillId":"scout"}
cap skill.run {"skillId":"scout","quantity":5,"memberSource":"existing"}
cap skill.cancel {"skillId":"scout","all":true}
cap map.explore {"formationId":"1队","regionName":"三楼右下"}
```

专用侦察队默认名称为 `侦察-<短ID>`，实际名称在命令卡片显示。可指定未被占用的新队名，不覆盖现有队。全部匹配单位缺失时报告失败，不暗中改为生产。

## 定义与展开

`SKILL.md` 的 `skill` JSON 块声明 ID、语义版本、名称/别名、适用游戏、参数及默认值、能力引用、两步依赖和探索策略。当前有限流程为“生产并编队，或使用已有成员 → 首名成员完成交接 → 探索”。宿主只支持这一类依赖，不解释任意工作流或执行 MD 附带的 JS。当前探索策略为各目标分区分别达到至少 60% 覆盖，优先中心及中心附近、候选间隔 6 格、优先内缩 3 格的区内落点、600 tick 原地停滞后换点、同区连续三次停滞后暂缓、收尾额外重试一轮；这些参数随运行捕获，后续可根据体验调整。

解释请求只装配简短 Skill 索引。绑定器展开为一个全局准备目标与一个专用编队探索目标，分别复用现有脚本生成、替换、运行和修复机制。探索脚本可提前编译等待成员；只有完成归属与停车确认的成员才进入动态可控列表，第一条狗无需等待其他狗出生。宿主每步提供目标落点，生成的编队脚本负责实际移动及避免重复发令。没有第二套微操器。

一条普通“探路”命令通常为一次理解、全局及侦察队各一次生成。分区和路点变化只更新本机事实，不继续请求云模型；校验重试、归属变化后的重新绑定及故障修复仍沿用现有机制。

`prompt-loader.ts` 原子加载模板、能力、游戏目录、战术和 Skill，全部内容参与提示版本。自定义模板目录须是 `<根>/prompts/templates/`，同根提供 `skills/`。新命令捕获 Skill 版本、内容哈希、正文、参数和地图方案；后续编译或修复从该目标读取已捕获正文，不把磁盘修改热换进正在运行的 Skill。错误重载保留进程上一套完整定义。

## 覆盖与停滞

探索范围取当前分区多边形与引擎有效范围的交集，再展开为原生格子，按地图、方案和有效范围内容哈希缓存；按行让出事件循环。几何和完整格子表保留在宿主，不发送给模型或侧栏。冰天雪地的 `maps/ice/playable-area.json` 由原生地块高度和当前 ra2web 的 MapBounds 规则离线生成，排除导图中存在但引擎范围外的格子；这些格子既不计入覆盖分母，也不作为落点。此范围不等于步兵通行性，图内水面和障碍仍交给观察与游戏寻路判断。运行时不依赖原始地图素材。

页面 `map.visible(x,y)` 表示格子已揭开黑幕；`map.tile(x,y)` 只返回可读取的地块。二者不能证明当前交战视野，也不能证明步兵可达。仅在实际返回已揭开且存在的地块时计入覆盖；未知和图外格子不算已覆盖。历史已揭开的覆盖累积保留。

仅有活动探索目标时读取，每次至多 256 格、同一时间至多一个页面读取，优先当前落点和成员附近，其余格子循环扫描。不是每步扫描整张地图，进度有分批观察延迟。页面读取前后核对同一对局；取消或换局后的迟到结果丢弃。已确认水面、墙、悬崖地块不作为步兵目的地，桥上地块例外；未知地形不据此提前判为不可达。

中心由有效格子的几何重心确定，再选取最近的区内有效格子，避免异形区重心落在孔洞或图外。每区先朝中心及其附近未知格子移动，实际覆盖不足 60% 才逐步向外展开，达到下限后离开，不为补边角贴边绕行。

侦察成员各自独立接收落点，同一步可给所有可用成员发令，不等待其他成员完成路程。优先占用尚无成员前往的分区；剩余分区较少时在同区选择相隔至少一个候选间距的落点协作。优先内缩 3 格的区内未知候选，窄区或区内候选已揭开时再回退到其他格子；稀疏候选被占用时也可用其余格子，避免有工作却让成员空等。走到分区中心、API 移动提交成功或模型记住“来过”均不能增加覆盖。只在成员实际位置长时间不变时判定停滞，允许绕路暂时远离终点。失败点附近小范围避让，避免紧邻同一障碍连续消耗额度；累计失败保留用于复盘，区域真实覆盖增加时清除连续失败和重试计数。同区连续三次停滞先暂缓并处理其他区域；其余工作完成后，对暂缓区额外换点重试一轮，优先换成员。仍无新进展且额度耗尽才部分完成，不把几个失败点直接当作整个区域永久不可达。

每个目标分区的已揭开格子数分别达到该区有效格子数的至少 60% 即达标，所有目标分区都达标才完成；全图加权平均达到 60% 不能替代逐区达标。已达标分区释放原落点并停止分配新落点，成员转向未达标区域，不追求各区全部揭开。只指定一个分区时只判断该区。剩余区域多次停滞时标为部分完成；全灭后若本次固定生产仍在进行则等其余成员，固定准备已结束且无人可用时显示部分完成或失败。不追加无限补狗、不主动改为进攻。结果保存结束时的覆盖，后续其他队揭开地图不会改写这次历史成果。侧栏分别显示生产进度与已达标分区数，并标明逐区阈值及未达标区域的实际覆盖，异常原因和用户反馈沿用现有命令卡片。

## 生命周期与持久化

每次调用有稳定运行 ID，关联原命令、Skill ID/版本/哈希与源文本、目标 ID、专用编队及地图/方案版本。运行协调与探索事实在 `packages/runtime/src/exploration.ts` 和运行时中维护；命令展开在能力绑定器，观察与几何准备在 `apps/companion/src/exploration.ts`。

取消只停止自身后续步骤及未完成目标，其他全局目标继续；已进入游戏队列的生产不撤回。侦察队的新命令实际生效后，旧 Skill 结束为 superseded，未完成的准备停止；旧流程不会重新接管。普通新命令生成失败时仍保留原任务。暂停、停止沿用现有生命周期机制。

状态写为 v4：保留原目标、生产记录、归属、交接和脚本，另存 Skill 运行、观察覆盖、扫描游标、落点及停滞事实。兼容读入无 Skill 数据的 v3，预留生产仍恢复为 unknown，不重放。首次写 v4 前备份旧格式文件；跨局隔离保持不变。对局归档保留 Skill 来源及精简区域进度，不把全格子表反复写入事件。

真实模型生成效果和地图寻路仍由用户在游戏中验收。本阶段不接麦克风、不新增归档 UI，也不采集画面。
