# 生产取消

“停止造矿车”“把飞机制造停了”和 `goal cancel <目标ID>` 经同一个 `goal.cancel` 入口执行。生产目标立即取消后续下单，并撤销自己已提交、尚在游戏队列中的数量。已造出的单位保留，其他目标继续；其他活动生产仍需的共享前置保留。全局停止、编队停止和 Skill 取消仍只停止后续调度，不扩大为取消全部生产。

例如要求造 4 架飞机，已造 2 架、队列还有 2 架时，取消只向游戏提交撤销剩余 2 架。队列撤销确认后，后来再要求生产飞机能够正常开始，旧提交不会吸收新飞机或阻塞新目标。

## 执行与确认

- 宿主使用本目标的生产提交和最新同名队列计算撤销量；桥在调用公开 `cancel(name, quantity)` 前再次按真实队列限量，不处理其他名称。
- 取消目标立即使旧动作及待编译候选失效。通常不重编其他目标；取消中断了同一控制对象的待生效变更时，才重新生成尚需接管的目标。
- API 返回只表示请求已提交。原生产卡片先显示“已停止追加／等待队列撤销确认”，随后按新快照显示实际撤销量；同时正常完工的单位计入产出，不计作撤销。
- 原始提交量、真实产物 ID、累计撤销量分别保存。只确认实际撤掉的数量；提交尚在途中或只看到部分入队时，未决部分保留，后来入队后继续撤销。
- 同名撤销依次确认，避免一次队列减少被记到多个提交。队列 API 不提供任务归属，宿主依赖已有的同名生产串行记账，不声称可区分玩家手工加入的同名项目。

## 持久化与异常

撤销请求发送前保存检查点，沿用 v4 格式的可选字段，兼容无撤销信息的旧 v3/v4 状态。预留或回执不明的撤销在恢复后继续观察，不盲目重发；检查点保存失败则不调用游戏，下一次快照再尝试。

生产目标取消后，其在途生产回执仍保留。旧版本已取消但仍有未决提交的目标会出现在理解上下文，可重新说“把飞机制造停了”处理剩余队列。只停止过、尚未明确要求撤队列的旧目标不会在升级时自行撤销。

当 API 结果不明且队列未能证明撤销时，保留未决记录并反馈；不把未知状态当作已取消，也不通过清空账本释放额度。产出和撤销随同局检查点及既有对局记录归档，不增加截图、录屏或模型复核调用。

## 验证

离线用例覆盖反馈中的“4 架已造 2 架”、未入队取消、保留其他生产、取消后重新生产、旧取消目标补撤、重复取消及重启、检查点失败、迟到入队和撤销时恰好完工。用户已于 2026-10-27 在 Companion 验收通过。
