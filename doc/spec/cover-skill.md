# 掩护 Skill

用户于 2026-10-27 批准[开发计划](../roadmap/cover-skill.md)，实测后明确授权后续阶段合并实施。当前 `cover@0.2.1` 接通同队角色、明确生产后的接入、预测跟随、近身站位、跟打和防空优先，待用户整体验收。

## 命令与成员来源

| 命令 | 行为 |
| --- | --- |
| 5辆坦克组成1队，5条狗掩护 | 使用现有单位，十个成员都属于真实1队，区分受护／掩护 |
| 造5辆坦克编入1队，2个IFV掩护1队 | 坦克生产并编队，掩护承接新造语境，优先现有IFV，不足补差额，交接后赋予角色 |
| 造2辆IFV掩护1队 | 明确新造两辆；同句已安排的IFV生产会复用，不重复造 |
| 1队里的IFV负责掩护 | 调整现有同队成员角色，不生产、不重建队伍 |
| 1队移动／巡逻／守区／进攻 | 保留掩护关系，由同一协调器形成该队最终动作 |
| 取消1队掩护 | 保留队伍和当前任务，解除角色；取消掩护自身追加的准备，独立明确生产继续 |
| 停止1队 | 停止整队行动，不自行恢复；后续新命令仍可使用保存的角色 |

`formation.cover.memberSource` 与 `skill.run cover` 支持 `existing/auto/new`。未提生产时用 `existing`，不足先用可用部分并反馈；`auto` 补本次数量差额；`new` 明确新造。`selector/quantity/unitIds` 选择掩护成员，`protectedSelector/protectedQuantity/protectedUnitIds` 选择受护成员。同句已有生产或编队承接该队，内部不创建额外护卫队。

只支持地面步兵和车辆担任掩护，不包括飞行、水上和跨队护送。新造受护成员沿用 `production.produce`，建造前置由已有科技树处理。绑定重决策必须保留双方成员、数量、来源和掩护职责，不能将掩护降为仅生产后显示成功。

## 生产、交接与归属

角色保存现有成员 ID，以及有限生产目标 ID 和数量。只接收这些生产记录的真实产物，停车交接确认后才开放指挥；不按兵种持续吸收后来生产的同型单位。首对可用成员可先行动，剩余本次成员陆续加入；移动及路线不会在本次准备尚未结束时提前完成。

实际已经分配过角色的 ID 留下历史，转出后不会被生产来源重新拉回。追加安排可保留原有角色和未完成来源，改令／重启不重复生产、不重置产物或交接。取消掩护只取消自身追加的准备和剩余队列，保留既有产物；原本独立明确下达的生产不受影响。解散时撤销掩护准备，独立生产继续但解除该队关联，避免自动重建已解散的队。

## 协同行动与站位

速度来自本局公开 `rules().speed`，是游戏规则解析值，不通过位移计时估算。当前引擎 `iniSpeedToLeptonsPerTick` 按 `min(256, 256×Speed/除数)` 换算为内部距离/tick；Ship/Vehicle/Chrono移动模型的除数为65，其余模型（包括警犬步兵）为100。每格256内部单位，因此直接用 `speed/256` 得到格/tick，不能把原始Speed或API值直接当作格/秒。预测使用游戏tick，不依赖现实帧率。

最慢成员直接接受终点移动指令，同速的最慢成员可一起直达；同一目的地不周期性重发或停车。其余成员按最慢成员的规则速度、角色间距和公开移动向量的地面x/z方向追随滚动前视点。航向轻微变化、转弯短暂停顿或预测点略落后不使队员来回掉头；预测点明显变化才更新，正常行军不以反复stop维持节奏。更快掩护和更快受护成员共用同一算法。缺少速度规则时保守跟随当前队伍位置，不猜一个速度值。

引擎负责寻路，位置反馈用于转向、严重脱队和堵路纠偏；严重脱队才临时停车重聚。接敌时再切换近身站位与就地开火。按距离受护主体最近的可见敌人确定威胁方向，掩护前出约两格、有限横向分散；无敌人时沿行军方向，待命时保持附近。慢成员抵达、实际交接和全队前后差参与到达判定，不能仅凭80%快成员先到而跳过慢成员。

站位持续受阻时回靠受护成员所在的实际格子；多次无位置进展会显示“队形受阻”，允许立即改令。先保持近身，再争取理想威胁前侧。没有引擎整队限速或永久禁止追击入口，队形按控制周期纠正，采样之间仍可能短暂偏离；复杂悬崖和窄路的停走观感需实机验收。

## 开火与防空

本机协调器记录已确认提交给受护成员的攻击目标。普通掩护只支援这些目标：当前武器兼容、当前站位在射程内且贴近受护成员时才攻击。射程不足、目标消失或偏离队伍时继续站位／回靠，不暂停整队，也不通过 `attackMove` 独自追敌。仅由游戏自动索敌形成、没有公开目标字段的攻击无法可靠读取，不猜测这类目标。

防空掩护优先选择当前射程内的近处空中敌人，再支援受护成员目标。空地层读取公开 `zone`，兼容空中步兵。进攻基地时允许掩护成员近身对空自卫，但不扩大受护成员的基地目标；区域清敌的自卫仍受真实分区范围约束。

当前武器与射程通过批量 `weaponVs(id,target,'current')` 只读查询，最多64对，放在 tick 采样外。掩护最终攻击携带 `holdPosition`，提交前再由桥用 `inRange(...,'current')` 确认；不足时正常等待。该处理只用于掩护协同，普通攻击继续由游戏处理接近、寻路和开火。

受护成员全部失效时，掩护成员停止并等待新命令；玩家明确下达新的行动时解除已经失去对象的旧关系，剩余成员正常行动，不被旧角色永久阻止。掩护成员损失时，受护成员继续原任务，不自动补兵。暂停、停止、取消、转队、解散与新命令继续受对局身份、控制对象代次、唯一归属和动作预算约束。

## 持久化、反馈和验证

编队可选 `cover` 保存策略、角色和生产来源；Skill 运行保存定义来源、准备归属、已分配 ID 和 `preparing/covering` 状态。目标保存行军、发令、预测航向及必要停滞事实，v4 兼容旧无掩护／无预测状态。领行失效或规则速度变化后重新选择基准，恢复不重放生产。只持久化被实际确认的动作，不把计划当作已经攻击或已经加入。

侧栏复用现有命令与反馈入口，显示角色人数、生产／交接等待、协同行军、进攻支援和队形受阻。v3 对局记录按已有变化格式保存，不保存每轮射程查询表，不增加截图、录屏或额外模型评估。

关键离线检查覆盖快／慢掩护、真实命令展开与实际隔离脚本运行、有限产物来源、逐个交接、半途重启、转队、暂停停止、取消与解散、威胁换向、近身跟打、防空优先和提交前射程复查。实际游戏观感由玩家验收。
