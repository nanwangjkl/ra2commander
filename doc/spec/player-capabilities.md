# 玩家基础能力

阶段 B 的能力目录位于 `prompts/capabilities/`。每项能力的名称、参数、默认值、选择方式、行为说明与反馈约定只在对应 Markdown 声明；绑定器实现位于 `apps/companion/src/capabilities/`。开发命令见 [AGENTS.md](../../AGENTS.md)，分期范围见[改造方案](../roadmap/capabilities-prompts-and-skills.md)。

## 命令链路

自然语言经一次模型理解，返回能力 ID 与参数：

```json
{"summary":"把现有步兵编入1队","operations":[{"capability":"formation.assign","params":{"formationId":"1队","selector":"infantry","quantity":5}}]}
```

加载器从 Markdown 的 `capability` JSON 块取得参数定义，校验模型输出并补默认值。TS 参数类型由同一份定义生成，调用输入类型与补齐默认值后的绑定器类型分别生成；参数契约变化而尚未生成类型时，加载明确失败或保留上一套完整定义。不会通过强制类型转换把模型任意字段直接送入运行时。

共同分派器 `executeCapabilities` 绑定当前单位、编队、目标与地图。生产、编队组织、补员、集结进入全局目标，作战进入对应编队目标；同一次命令按控制对象合并编译。停止、暂停与无需重编的恢复由宿主直接执行，不额外请求脚本生成。普通指令仍是理解与脚本生成两段，逐 tick 不调用云模型。

终端的 `form`、`produce`、`task`、`reinforce`、`rally`、`goal` 和 `global` 保留语法，作为同一入口的适配器。`cap <能力ID> <JSON参数>` 可直接调用目录中的所有能力；`cap list` 查看目录。侧栏和 `say` 都进入同一自然语言链路，后续 ASR 也将把转写文本送入此处。

## 当前能力与接线

下表各项均已有底层实现、Markdown 声明、绑定器、终端及自然语言入口。“自动检查”指隔离环境中的接线、目标和状态检查；云模型理解与真实对局效果仍待玩家验收。

| ID | 行为 | 自动检查 |
| --- | --- | --- |
| `base.deploy` | 展开一辆现有基地车 | 展开绑定及转换完成 |
| `production.produce` | 建筑/步兵/车辆/飞机生产，可关联新造单位编队 | 前置、累计产量、生产后交接 |
| `production.power` | 持续补电 | 待建电厂复用及缺额计算 |
| `formation.create` | 新建编队 | 现有成员交接 |
| `formation.assign` | 现有单位编入，必要时建队 | 终端/自然语言一致、坦克与步兵、不追加生产 |
| `formation.transfer` | 从现有集合或指定来源转编 | 成员实际归属和停车交接 |
| `formation.dissolve` | 解散编队 | 原成员回到未编队状态 |
| `combat.move` | 前往地名或坐标 | 绑定目的地、实际到达完成 |
| `combat.hold` | 持续守区，可附战损回撤 | 分区就位后保持持续状态 |
| `combat.clear-region` | 只清理指定分区敌人 | 异形边界、行军与攻击范围分开 |
| `combat.attack-all` | 指定队或全体现有作战队进攻 | 单队改令保留其他队伍 |
| `management.reinforce` | 从未编队或指定来源持续补员 | 按缺额转入，不追加生产 |
| `management.rally` | 未编队成员集结 | 实际选择及移动动作 |
| `control.stop` | 停止编队/全局/全部脚本/所选单位 | 取消在途生成、迟到结果失效 |
| `control.pause` | 保留目标与进度，暂停脚本 | 状态与无额外编译 |
| `control.resume` | 恢复保留目标，必要时重编 | 累计进度不重放 |
| `goal.cancel` | 取消一个已有目标 | 其他目标继续、保留提交记录 |
| `goal.edit` | 修改已有生产目标总量 | 只补剩余数量、生成失败保留旧目标 |

`eval`、截图、地图绑定、资源导入、模型切换、查询列表与人工核对 `goal resolve` 属于环境或调试入口；原始 `move/amove/gather/attack` 仍供调试。它们不作为自然语言玩家能力声明。

## 对象与状态

- 选择器共用现有单位 ID、具体兵种名称及 `tanks/infantry/vehicles/aircraft/all`，编队数字别名与楼层数字在绑定时统一。规则目录同时读取当前可造项目和已有兵种，覆盖步兵与飞机；阶段 C 已把当前游戏的阵营候选、角色与前置类别集中到游戏目录，实际规则仍由对局查询。
- 定量编入默认使用未编队成员；明确全部时可合并其他编队，已在目标队内的不重复转入。不足时执行可用部分并反馈，不自动生产。
- 移动与守区分别判断结束。守区的 `destination` 是就位点，`mode=hold/assault` 到达后持续；区域清敌不以到达或暂时无敌人判定完成。
- 暂停保留脚本和进度，已发给游戏的行动可能继续；需要停车及撤销目标时用停止。停止、取消不自动撤回已经投入的生产。
- 修改生产目标的总量，原卡片继续跟踪稳定目标，修改命令反馈本次变更结果；修改生成失败时原有效目标继续。已完成目标增加总量后继续累计进度，生成失败仍保留原来的完成事实。
- 无新目标的控制命令也保存结束状态，重启可恢复当前局卡片，不重放动作；不扩展为完整跨局历史。

参数校验失败或部分对象缺失只反馈相关项，其余可执行项继续。地图候选点的实际可达性、清敌覆盖与引擎寻路效果仍以游戏事实为准。

## 开发约定

每个文件名与能力 ID 相同，包含一个 `capability` JSON 块。参数支持 `string/integer/number/boolean/integer[]`、必填、默认值、枚举、数值与数组长度约束；整数数量可声明 `allowAll`。参数之间的语义约束和实际游戏对象可用性由绑定器检查。

编辑说明可在下一条命令生效。修改参数、默认值、ID 或绑定器声明后，运行类型生成与检查并重启 Companion。新增能力还需实现对应绑定器，检查会指出缺少实现或未声明入口；仅增加 Markdown 不会让系统拥有新的游戏操作。

能力目录、四份模板、当前游戏目录与战术主题共同计算提示版本，整套加载通过后才生效，同一命令固定同一版本。加载错误反馈具体文件并保留进程上一份可用定义。Skill 的组合、依赖和探索事实将在阶段 D 实现。
