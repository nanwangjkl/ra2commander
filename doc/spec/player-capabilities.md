# 玩家基础能力

阶段 B 的能力目录位于 `prompts/capabilities/`。每项能力的名称、参数、默认值、选择方式、行为说明与反馈约定只在对应 Markdown 声明；绑定器实现位于 `apps/companion/src/capabilities/`。开发命令见 [AGENTS.md](../../AGENTS.md)，分期范围见[改造方案](../roadmap/capabilities-prompts-and-skills.md)。

## 命令链路

自然语言经一次模型理解，返回能力 ID 与参数：

```json
{"summary":"把现有步兵编入1队","operations":[{"capability":"formation.assign","params":{"formationId":"1队","selector":"infantry","quantity":5}}]}
```

加载器从 Markdown 的 `capability` JSON 块取得参数定义，校验模型输出并补默认值。TS 参数类型由同一份定义生成，调用输入类型与补齐默认值后的绑定器类型分别生成；参数契约变化而尚未生成类型时，加载明确失败或保留上一套完整定义。不会通过强制类型转换把模型任意字段直接送入运行时。

共同分派器 `executeCapabilities` 绑定当前单位、编队、目标与地图。生产、编队组织、补员、集结进入全局目标；攻击和采矿按成员归属进入全局或对应编队目标；同一次命令按控制对象合并编译。停止、暂停与无需重编的恢复由宿主直接执行，不额外请求脚本生成。普通指令仍是理解与脚本生成两段，逐 tick 不调用云模型。

正常情况下，整句话理解一次，再为每个需要变更的控制对象生成一次脚本，通常为 `1 + 控制对象数` 次模型请求。多个生产/建设/管理子命令合在一份全局脚本；“生产坦克、1队去A、2队去B”为一次理解加三次生成。纯停止等直接控制通常只有一次理解。当前不同控制对象的生成请求依次发出，脚本生效后由本机快照调度各自持续执行，不额外请求模型做逐步决策。校验重试、成员变化后的重新绑定及自动修复会增加请求次数。

协作依靠宿主共享的目标、生产记录、唯一成员归属和停车交接：生产前置复用，编队移动等待实际成员；同句话对同一队的多个有序移动合成一条路线。它还不是任意条件和任务之间的通用依赖图。单句理解当前最多返回八个能力调用，合并为目标后按控制对象生成脚本。

终端的 `form`、`produce`、`task`、`reinforce`、`rally`、`goal` 和 `global` 保留语法，作为同一入口的适配器。`cap <能力ID> <JSON参数>` 可直接调用目录中的所有能力；`cap list` 查看目录。侧栏和 `say` 都进入同一自然语言链路，后续 ASR 也将把转写文本送入此处。

## 当前能力与接线

下表各项均已有底层实现、Markdown 声明、绑定器、终端及自然语言入口。“自动检查”指隔离环境中的接线、目标和状态检查；云模型理解与真实对局效果仍待玩家验收。

| ID | 行为 | 自动检查 |
| --- | --- | --- |
| `base.deploy` | 展开一辆现有基地车 | 展开绑定及转换完成 |
| `base.relocate` | 收起基地、搬至分区或坐标、重新展开 | 形态换 ID、实际抵达、候选换点、依赖建造与恢复 |
| `building.repair` | 原生扳手修复本次选定的受损建筑 | 幂等开启、缺钱等待、实际满血完成与恢复 |
| `building.sell` | 出售本次选定的现有己方建筑 | 禁售与车辆过滤、实际离场、迟到回执与恢复 |
| `economy.gather` | 现有矿车在指定分区内持续采矿，不区分矿种 | 公开矿格、并行分配、不打断返厂、改令和恢复 |
| `production.produce` | 建筑/步兵/车辆/飞机生产，可关联新造单位编队及明确的建筑方位 | 前置、累计产量、生产后交接 |
| `production.power` | 持续补电 | 待建电厂复用及缺额计算 |
| `formation.create` | 新建编队 | 现有成员交接 |
| `formation.assign` | 现有单位编入，必要时建队 | 终端/自然语言一致、坦克与步兵、不追加生产 |
| `formation.transfer` | 从现有集合或指定来源转编 | 成员实际归属和停车交接 |
| `formation.dissolve` | 解散编队 | 原成员回到未编队状态 |
| `combat.move` | 前往地名或坐标 | 绑定目的地、实际到达完成 |
| `combat.hold` | 持续守区，可附战损回撤 | 分区就位后保持持续状态 |
| `combat.clear-region` | 只清理指定分区敌人 | 异形边界、行军与攻击范围分开 |
| `combat.attack-all` | 指定队或全体现有作战队进攻 | 单队改令保留其他队伍 |
| `combat.attack` | 按选择器或 ID 指挥现有成员攻击，无需建队；飞机单次出击 | 逐机装弹等待、实际发射完成、范围保留与恢复 |
| `management.reinforce` | 从未编队或指定来源持续补员 | 按缺额转入，不追加生产 |
| `management.rally` | 未编队成员集结 | 实际选择及移动动作 |
| `control.stop` | 停止编队/全局/全部脚本/所选单位 | 取消在途生成、迟到结果失效 |
| `control.pause` | 保留目标与进度，暂停脚本 | 状态与无额外编译 |
| `control.resume` | 恢复保留目标，必要时重编 | 累计进度不重放 |
| `goal.cancel` | 取消一个已有目标 | 其他目标继续、保留提交记录 |
| `skill.run` | 展开探路或维修车 Skill | 参数、生产交接、实际组装与持续执行 |
| `skill.cancel` | 取消 Skill 自身后续步骤 | 保留其他目标、旧流程不再接管 |
| `transport.enter` | 未编队步兵进入指定己方载具 | 实际载员确认，不新增生产 |
| `vehicle.repair` | 指定队分头维修受损坦克，可跟随其他队 | 全量血量、独立分工、无伤员待命 |
| `map.explore` | 已有编队按实际揭示覆盖探索 | 分散落点、停滞换点、实际覆盖与部分完成 |
| `goal.edit` | 修改已有生产目标总量 | 只补剩余数量、生成失败保留旧目标 |

`eval`、截图、地图绑定、资源导入、模型切换、查询列表与人工核对 `goal resolve` 属于环境或调试入口；原始 `move/amove/gather/attack` 仍供调试。它们不作为自然语言玩家能力声明。

## 对象与状态

- 选择器共用现有单位 ID、具体兵种名称及 `combat/tanks/infantry/vehicles/aircraft/all`，编队数字别名与楼层数字在绑定时统一。`combat` 按本局武器与角色选出作战部队，包含灰熊和多功能步兵车，排除矿车、基地车、工程师与建筑；`vehicles` 仍表示全部车辆，不能替代战斗单位。理解请求的 `self.isCombat` 提供同一判断。规则目录同时读取当前可造项目和已有兵种，覆盖步兵与飞机；阶段 C 已把当前游戏的阵营候选、角色与前置类别集中到游戏目录，实际规则仍由对局查询。
- 定量编入默认使用未编队成员；明确全部时可合并其他编队，已在目标队内的不重复转入。不足时执行可用部分并反馈，不自动生产。
- 同一句话对同一编队的多个成员选择合并为一个目标并去重，避免两个建队请求互相阻塞。原话归一化保持操作原位；“编入后移动”可先绑定尚在建立或生产补入过程中的编队，移动目标等待归属交接完成才开放成员，建队后初始化真实成员基准。
- 移动与守区分别判断结束。守区的 `destination` 是就位点，`mode=hold/assault` 到达后持续；区域清敌不以到达或暂时无敌人判定完成。
- 同句话的同队多个 `combat.move` 合成一个 `route`，按原话顺序经过所有站点。`patrol=true` 允许沿途交战，明确终点的路线走完一次后完成；普通移动不增加攻击权限。“基地附近”按本局己方建造厂（或尚未展开的基地车）位置绑定。路点索引由宿主保存，实际到达后推进，本步 `spec.destination` 已是当前站，脚本不能自行猜路点或另写循环；侧栏显示已到达路点数及当前目的地。之后另一句话的新命令仍正常替换该队旧路线。
- 移动与集结按部队主体到达判定：半径随当前存活受控人数增长（目前 `max(3, ceil(2.5×√N))` 格），至少 80% 成员进入范围即可结束当前移动或推进路点，不强求全员靠近一个坐标。少量掉队成员仍在队内，后续路点指令仍包含它们；仅少数前锋到达、无人或仍在交接的成员不能凑成到达事实。`GoalView.arrival` 提供 `reached/radius/nearby/required/total/laggingUnitIds`，脚本使用同一判定，避免再加更严的全员挤点条件。该状态不表示区域清敌完成。
- 暂停保留脚本和进度，已发给游戏的行动可能继续；需要停车及撤销目标时用停止。停止、取消不自动撤回已经投入的生产。
- 编队新命令实际生效后替换旧目标；取消状态保存具体原因。侧栏对正常改令显示“已被新命令替换”及新原话，和玩家取消、脚本停止、解散区分。
- 修改生产目标的总量，原卡片继续跟踪稳定目标，修改命令反馈本次变更结果；修改生成失败时原有效目标继续。已完成目标增加总量后继续累计进度，生成失败仍保留原来的完成事实。
- 无新目标的控制命令也保存结束状态，重启可恢复当前局卡片，不重放动作；不扩展为完整跨局历史。

参数校验失败或部分对象缺失只反馈相关项，其余可执行项继续。存在先后依赖的建造保留等待，不能在搬迁失败时退回旧址。地图候选点的实际可达性、清敌覆盖与引擎寻路效果仍以游戏事实为准。详见[基地搬迁与后续区域建造](base-relocation.md)。

## 开发约定

每个文件名与能力 ID 相同，包含一个 `capability` JSON 块。参数支持 `string/integer/number/boolean/integer[]/string[]`、必填、默认值、枚举、数值与数组长度约束；整数数量可声明 `allowAll`。参数之间的语义约束和实际游戏对象可用性由绑定器检查。

编辑说明可在下一条命令生效。修改参数、默认值、ID 或绑定器声明后，运行类型生成与检查并重启 Companion。新增能力还需实现对应绑定器，检查会指出缺少实现或未声明入口；仅增加 Markdown 不会让系统拥有新的游戏操作。

能力目录、模板、当前游戏目录与战术主题共同计算提示版本，整套加载通过后才生效，同一命令固定同一版本。加载错误反馈具体文件并保留进程上一份可用定义。Skill 索引与正文也参与同一版本。阶段 D 探路已获用户认可，见[探路 Skill](scouting-skills.md)。第二个[维修车 Skill](repair-vehicle-skill.md)增加 transport.enter（步兵上车）与 vehicle.repair（编队维修支援）两项能力，维修车加入时共23项；新增基地搬迁后共24项。生产、现有组件编队、实际组装和并行维修由同一 Skill 展开，selector=repairVehicles 按实际载员选择成品维修车。

建筑生产的可选方位参数、画面投影与实际位置确认见[建筑方位要求](building-placement.md)。只有原话提到方位时生成位置约束，其他项目与必要前置不继承。

名称绑定按操作类型消歧；语音失败项限次重决策，可执行部分先运行。执行错误及有条件却无进展的脚本携带近期动作与结果进入模型修复，详见[自动恢复](automatic-recovery.md)。

`economy.gather` 将指定分区采矿与普通集结分开。未编队成员走全局，已有小队沿用独立脚本；目标持续执行，抵达不等于完成。详见[指定分区采矿](regional-mining.md)。

生产项目通过自动导入的完整游戏目录识别，包括未解锁的单位和建筑；必要科技前置与生产设施由同一规划器补齐，不需要逐单位添加能力或建造配方。见[完整游戏目录](full-game-catalog.md)。

现有成员攻击与飞机单次出击详见[攻击与出击规范](selected-attacks-and-sorties.md)。攻击不要求先建队，飞机装弹时为 pending，逐机满弹后独立出击，实际发射一次即完成。

现有建筑的原生扳手维修与出售见[建筑操作](building-operations.md)。当前共28项基础能力；建筑维修不调用维修车，出售不扩大到车辆或后续新建建筑。
