# 游戏目录、规则事实与战术约定

阶段 C 将当前游戏目录集中在 `prompts/games/current-mod.md`，将执行约定拆到 `prompts/tactics/`。它们和基础能力、固定模板一起加载和计算提示版本；Skill 的探索与步骤协调仍留在 D。

## 当前游戏目录

当前配置明确选择 ra2web 的共和国之辉，覆盖盟军、苏军和中国。候选名称和类型已对照本地游戏目录的 `res/overlay/rules.ini` 核对；目录提供角色与查询提示，实际对局的地图、MOD 覆盖仍以公共 API 结果为准。不根据地图名称或单位前缀自动判断 MOD。

Markdown 中的 `game` JSON 块声明游戏 ID/版本、阵营及基地识别对象、角色别名、候选原生名称和类型、前置类别与有限规则匹配条件。正文说明适用范围与规则优先级。当前角色为：

| 角色 | 用途 |
| --- | --- |
| `constructionVehicle` / `constructionYard` | 基地车、建造厂与阵营识别 |
| `powerPlant` | 普通电厂及引擎确认具有正供电的项目 |
| `refinery` / `barracks` / `warFactory` | 矿场、兵营、战车工厂 |
| `radar` / `technology` / `spySatellite` | 雷达、科技设施、间谍卫星 |
| `tank` | 坦克选择；排除引擎明确标记的矿车、海军单位 |
| `scoutDog` | 侦察犬候选，用于现有生产和成员选择 |
| `engineer` / `harvester` | 工程师、矿车 |

候选是查询入口，未读取到规则的项目不进入模型可用目录。当前可造项目和已有单位也会被查询，因此新增实际单位不必都预写在静态候选中。类型、供电及明确角色标记优先使用真实规则；静态名称只在缺少对应事实时提供提示。

生产名称、角色别名与同类阵营误选共用 `GameCatalog` 解析。选择顺序考虑精确名称、实际可造性、当前阵营和已有设施；多个合理候选直接选择并反馈。明确可造的跨阵营项目可以使用。具体单位编队按其真实名字或角色筛选，不把明确的某个兵种扩大成同类全部单位。

## 前置与生产事实

目录只把 `POWER`、`PROC`、`BARRACKS` 等类别映射到当前游戏的具体候选，不另写一套科技树。`prepareGoals` 按真实 `rules().prerequisite` 计算必要前置，当前引擎确认可造的项目跳过父级递归。同一次准备复用规则查询；新的请求重新读取，不跨局缓存规则。

已有建筑满足前置，已提交前置继续复用，目标本身按玩家明确新增数量累计。引擎确认目标可造后，历史前置清单不再引发新的额外建设。真实规则无法读取时报告具体目标，保留当前有效脚本。

宿主在每次已有快照计算中给生产目标附上 `productionPlan`：

| 字段 | 含义 |
| --- | --- |
| `missingPrerequisites` | 当前仍未满足的必要前置 |
| `pendingPrerequisites` | 已有提交、等待出现的前置 |
| `availableToProduce` | 本步可造、有剩余额度且有队列空位的候选 |
| `readyToPlace` | 本步队列已就绪且允许放置的建筑 |

累计提交、产物观察、电力缺额、队列空位仍使用现有运行时记录；这些事实随快照更新，不让模型凭常识重算。候选列表帮助安排执行，动作仍经过本步权限、额度、归属及会话检查。局部受阻不应让其他可执行目标停止。

## 按需组合战术

`compile.md` 保留函数输出、快照、动作包装和宿主边界的基本契约。每份战术 Markdown 的 `tactic` JSON 块声明适用阶段、目标种类或恢复条件，正文保存固定指令。

| 文件 | 加载时机 |
| --- | --- |
| `common.md` | 理解与生成的通用行动原则 |
| `production.md` | 当前控制对象包含生产目标 |
| `combat.md` | 当前控制对象包含作战目标 |
| `management.md` | 当前包含编队组织、补员、集结或展开目标 |
| `recovery.md` | 自动修复或校验重试 |

混合目标加载所需主题的并集。普通编队脚本不携带生产约定；纯生产脚本不携带作战细则。修复和校验重试使用同一命令捕获的文件版本，编译尝试日志保留实际主题 ID。新增内容组合不增加模型调用次数，也不改变每编队与全局各一份脚本的机制。

普通攻击始终由游戏处理接近与开火；射程信息可辅助战术，不能被约定变成拒绝执行的条件。区域清敌仍按真实异形分区选敌，不能扩大到全图。

## 修改与验收

修改游戏目录、别名、角色候选或战术正文后运行 `pnpm prompts:check`。下一条命令会使用完整的新版本，已有脚本继续原行为；加载失败反馈具体文件并保留上一份完整可用定义。模型说明只附目录正文和当前实际候选，不反复传输全部静态候选表。

自动检查覆盖三阵营及侦察犬选择、Markdown 候选变更、实时规则覆盖提示、前置去重与队列就绪、主题选择及错误重载。真实模型对各种说法的理解、游戏中的可达性和建造效果仍由玩家验收。此阶段没有接入“探路”Skill、地图探索或录音。
