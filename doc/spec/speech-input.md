# 本地语音输入

2026-11-02 用户验收历史与设置页后，授权开始[新阶段 2](../roadmap/client-development-phases.md)。首版接入及本轮交互调整后，用户确认保持当前实现并要求提交推送；手动重新加载识别器保留，客户端打包未启动。

## 使用与交互

开发时首次运行 `pnpm speech:install` 安装官方 SenseVoice INT8 模型，再正常启动 Companion；正式包内置模型。页面默认尝试启用麦克风，Electron 对本机页面音频请求自动放行，普通浏览器首次需允许权限；按住默认反引号键（`Backquote`）说话，正常松开后识别并自动下令。也可按住右侧说话图标录音。启用设备本身不开始录音或下令；设备访问失败时回到文字输入，可通过左侧麦克风图标重试。

输入区为固定左中右三栏：左侧麦克风图标以灰色/绿色表示关闭/启用；关闭时中间为文本框、右侧为下令箭头，启用时用中间输入区的整块背景填充表示音量，框内文字显示 ``按住右侧按钮或`说话``、“正在录音，松开下令”“正在识别…”及错误，右侧为按住说话图标。取消单独的细音量条和框外状态行，长提示在框内单行省略，悬停可读全文；授权、录音、识别及异常均不改变工具栏高度。关闭麦克风后的错误使用输入占位提示、边框和悬停说明，保留文字编辑与草稿。两种右侧按钮等宽，语音模式不提交隐藏草稿。不常驻显示“麦克风未启用”等说明，授权中仅在麦克风按钮内显示旋转 loading；图标保留悬停说明与辅助标签。

设置页的“语音输入”只提供麦克风、录音键及保存/重新加载操作，模型目录由宿主统一解析；开发者可通过 `RA2C_SPEECH_MODEL_DIR` 覆盖。配置以版本 2 保存到 `.runtime/speech/settings.json`，只记录设备和按键；旧版本 1 保留设备/按键，旧路径字段不再控制识别器并在下次保存时移除。设备为空时使用系统默认。录音键可选反引号、右 Ctrl、右 Alt、F8、F9，文本编辑期间不拦截录音键。麦克风与游戏音频由不同音频图处理，采集图不回放麦克风。开启后可查看输入音量，关闭按钮立即释放设备。

快捷键同时监听工作台和同源游戏 iframe，页面重新加载时重新绑定；只在麦克风启用、识别器就绪时接管相应按键，屏蔽游戏对该次按键的处理。侧栏重连释放旧设备和录音后按此前开关状态重新启用；手动关闭、权限失败或修改语音设置后保持文字模式。重新打开页面默认启用语音，不自动录音。普通浏览器在首次用户手势之前可能暂停音频图，启用设备不等待此暂停结束，按下录音时再恢复。

一次录音在开始时创建命令 ID 和卡片，显示“录音中 → 识别中 → 原话及现有理解/执行状态”。重复 keydown、重复 keyup 和重复音频请求不重复下令；最终文本直接进入当前命令入口，不增加确认或独立模型决策。识别期间可继续输入文本、录下一句，已有游戏任务持续运行。

Esc 取消尚未交接的录音/识别；切出窗口、页面隐藏、设备断开、侧栏重连、换局或识别器重载也取消未交接语音。正常松开才提交音频，失焦不自动提交半句。录音达到 30 秒取消并提示分句；空音频、静音、拒绝权限、缺少设备和识别失败有明确提示。已经转交命令链路的文本不会被“关闭麦克风”误取消；游戏任务仍使用原停止、暂停和取消能力。

## 采集、识别与并发

`speech-audio.ts` 使用 `getUserMedia` 和 AudioWorklet；浏览器采集在独立音频线程中进行，按句在内存中编码到 16kHz 单声道 PCM16 WAV。宿主检查容器、时长和静音后才调用本地识别；默认不落盘或上传原始录音。

`packages/speech/` 使用 `sherpa-onnx-node` 2.0.1 和 SenseVoice INT8 中文识别。识别器在独立 Node 子进程中加载一次，逐句建立 stream；实时运行时、模型理解和其他脚本不等待原生推理线程。最多接收四条未完成语音，识别异常或超时明确失败，不自动重放音频或改用云端识别。设置中的“重新加载识别器”可恢复后端；退出终止子进程，父进程断开时子进程也退出。

语音松开并接收完整音频时，在现有 `TranscriptQueue` 预留位置；识别完成继续同一个顺序位置和取消信号。后来的普通文本命令可以同时理解，按原顺序绑定；停止全部可使更早识别失效，范围停止给旧语音保留范围规则，转写理解后只跳过相应部分。取消、识别失败和换局释放位置；脚本生成仍不占绑定队列，见[命令并发](command-concurrency.md)。

`VoiceCommands` 在识别完成及交接前重新检查本次状态、取消信号和对局身份；即使识别器不支持中途打断原生计算，迟到结果也不能执行。UI 卸载会取消请求、录音、监听和计时器，旧异步回调不能重新启用设备或写入新版状态。

## 数据与接口

- `source: "voice"` 标识真实语音；`recording`、`transcribing` 为命令阶段，其后使用已有阶段。
- 阶段事件的 `speech` 保存模型标识、音频时长和识别耗时；事件时间可与现有理解、绑定、首次动作对照，不给未实测机器承诺固定延迟。
- 转写原话、理解、实际执行、错误和反馈继续写入同一对局档案和 ZIP；不新增录音文件或第二套执行日志。识别模型和麦克风配置不进入调试包。
- `GET /commander/speech` 读取配置与识别器状态；`POST` 保存当前配置；`POST /commander/speech/reload` 重载本地识别器。
- `POST /commander/voice/<command-id>/start` 建立录音记录，`/audio` 接收一份 WAV，`/cancel` 取消尚未交接的语音。沿用同源检查、体积限制、HTTP/SSE 和现有命令 ID；不重试提交。

## 模型来源与当前边界

模型版本、来源、压缩包及各文件大小/SHA-256、许可说明集中在 `packages/speech/model-manifest.json`。开发环境模型正文位于已忽略的 `resources/speech/models/<model-id>/`，与 `.runtime/` 中的设置、对局和浏览器资料分开；旧默认模型校验后由准备命令移入资源目录，不重复下载。清单、准备与离线检查约定见[语音模型资源](../assets/speech-model.md)。

准备命令从 [sherpa-onnx 官方模型发行页](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models) 下载固定的 SenseVoice INT8 压缩包，先校验压缩包，再逐文件检查。有效模型直接复用，压缩缓存按内容哈希保存在 `.runtime/speech/downloads/`；异常目标目录不覆盖，解包校验失败不交付。`pnpm speech:check` 离线检查本项目固定模型版本，无需游戏或识别器。压缩包约 163 MB，准备后识别离线运行；运行库、模型和设置均不进入对局 ZIP。

正式程序随安装包内置模型，构建复用同一清单校验，宿主从安装资源解析模型目录，用户无需自行下载。`speech:install` 是开发环境的资源准备入口；正式运行和分发位置见[Linux 分发](linux-distribution.md)。

选型采用官方 [Node SenseVoice 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/nodejs-addon-examples/test_asr_non_streaming_sense_voice.js)及[模型说明](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)。相比原历史计划中优先考察的 whisper.cpp，本轮选择 Node 预编译运行库以复用现有启动与进程管理，不要求用户另装 Python、ffmpeg 或编译识别服务。模型自带许可说明按原文保留，不在本项目重新声明模型许可。

首版只接一套本地引擎，不做流式中间文字、唤醒词、后台全局热键或自动术语替换。SenseVoice 本方案不使用 transducer 热词参数；原始转写交给现有游戏目录与命令理解处理，红警术语与实际噪声效果由用户实机反馈调整。目前在 macOS Apple Silicon 开发环境验证，Windows 的设备、快捷键与完整安装体验尚待目标平台验收。
