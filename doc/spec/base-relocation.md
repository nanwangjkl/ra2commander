# 基地搬迁与后续区域建造

玩家于 2026-10-26 要求支持“把基地搬到一楼，在一楼造一个矿场”。搬迁属于全局管理目标，不把基地车当作战编队，也不生产额外基地车。

## 命令入口

`base.relocate` 接受 `regionName` 或 `x/y`，可用 `unitId` 指定现有己方建造厂或基地车；省略对象时优先空闲基地车，再选择建造厂。对象必须未编队。实际形态转换名称读取本局规则的 `deploysInto/undeploysInto`。

```json
[
  {"capability":"base.relocate","params":{"regionName":"一楼"}},
  {"capability":"production.produce","params":{"target":"矿场","quantity":1,"placementRegion":"一楼","afterRelocation":true}}
]
```

宿主预留本句话的搬迁目标 ID，再绑定相关建造目标。即使模型将调用顺序颠倒，也保留建造依赖。明确的 `afterRelocation` 关联本句话的搬迁；建造位置与本句话或当前活动搬迁的目标分区一致时，也自动等待该搬迁。未关联的独立生产继续执行。搬迁绑定失败时建造保留等待，不回退旧基地；失败项仍可进入限次重决策。

## 阶段与游戏接口

阶段由宿主根据真实快照推进，保存在 `GoalFacts.relocation`：

1. `packing`：给建造厂下 `werhd.move([id], x, y)`；引擎在本局允许基地重新部署时先收起，再移动。
2. `moving`：使用实际出现的基地车 ID 前往分区内部候选点。
3. `deploying`：基地车抵达候选点附近且位于指定分区内，才允许 `werhd.deploy([id])`。
4. `confirming`：等待实际形态转换，不能把接口接受当作已展开。
5. `completed`：确认转换后的建造厂实际出现在本次目标内，后续建造才解锁。

转换识别只匹配本次已请求的转换、预期名称、上一位置附近的新 ID；不接管原先已经存在的其他基地。丢失或无法唯一确认身份时先等待，超时如实失败。移动停滞或当前点无法展开时按有限区内候选换点；候选耗尽或建造厂始终无法收起时失败并说明原因，不增加生产。

新目标保存 `executionMode=native`，本机处理器直接提出本步 `relocation.action`，共用提交校验和预算；正常语音只需一次理解，直接能力调用无需模型，侧栏显示“本机执行”。固定实现异常记录供开发修正，不进入云端脚本修复。旧状态及显式回退的脚本目标继续读取 `g.relocation.action`，保留隔离的变形换 ID、移动、展开检查与有限修复。所有来源都按实际阶段和当前 ID 发令，不提前展开，并对重复请求节流。

## 建造依赖与位置

`ProductionGoal.afterGoalId` 要求对应搬迁状态为 `completed`，此前目标及其科技前置均不能提交。搬迁取消或失败后保持明确受阻，不在旧址继续。带位置要求或搬迁依赖的目标不被其他目标在旧址建出的共享前置抵消。

`production.produce.placementRegion` 绑定地图真实异形边界。它独立于上下左右方位；兼容旧理解在无方位时仅填写 `placementAnchor=一楼`。放置时由宿主注入区域，页面桥只向区域内、孔洞外且引擎 `canPlace` 允许的格子提交。区域无位置时保留就绪建筑，限频重试，不退回默认位置，也不额外重造。方位与分区可以同时约束；搬迁后以“基地”为参照的方位改用新建造厂位置。

完工按实际建筑快照的原生落格判定，逐座记录坐标与分区/方位是否满足；数量满足但位置错误显示部分达成。

## 取消与恢复

取消搬迁、停止全局或停止被管理的基地都会撤销后续步骤，并向当前实际单位停车。新搬迁替换同一基地的旧搬迁及其旧集结等指挥；其他命令接管当前基地时也撤销旧搬迁。原先依赖旧搬迁的建造不会擅自改目的地。所有迟到生成继续受取消信号与编译租约约束。

阶段、当前 ID、已见身份、候选索引、位置和发令时钟随 v4 状态保存。暂停时不累计停滞时钟；重连继续观察实际形态，不重放已完成收起和生产。新增字段是 v4 的可选扩展，已有不含搬迁的 v3/v4 状态继续兼容。实机效果由玩家验收，不自动下测试命令、截图或移动镜头。

默认只将新搬迁设为本机执行，旧 v3/v4 无标记目标保持脚本。用 `RA2C_RELOCATION_EXECUTOR=script pnpm companion` 单独回退搬迁：同一目标 ID、当前形态和进度、后续建造的 `afterGoalId` 均保留；等待代码期间继续观察已请求的真实变形并冻结停滞时钟，避免把变形误记成生产。后续新命令也走脚本。生产仍使用原有生成代码，搬迁完成依赖不会绕过。阶段 5B 已于 2026-10-27 由用户验收通过。
