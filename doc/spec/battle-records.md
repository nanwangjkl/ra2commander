# 对局记录与反馈

资料保存在本机，供玩家与开发者复盘；不自动上传、不自动过期删除。归档与运行检查点分离，读取、导出归档都不会执行游戏任务。沿用文件存储，不引入 SQLite，理由是事件追加和单局导出已满足当前需求。

## 界面与记录范围

指挥记录只显示当前局命令、实际理解、执行状态、错误和逐条反馈，不提供代码预览。反馈保存当时的状态与历次意见，后续完成不能改写旧反馈；写盘成功才确认保存，失败保留输入。无对局时不恢复历史未绑定对局的错误卡片，同局重连恢复同局卡片。

归档关联原话、模型请求/响应、提示版本、绑定结果、候选代码及校验、实际目标与产物、运行观察、错误和反馈。语音沿用同一命令 ID，仅保存时长和识别耗时等元信息，不保存原始录音。生产提交、脚本生效、抵达与目标完成分别记录。

胜负必须有公开玩家终态证据，关闭或刷新不推断结果。确认结束后停止调度和在途生成，作战目标按胜负结束，其他目标保存真实进度；同局恢复不继续已结束对局。

## 存储与兼容

| 路径：`.runtime/battles/<battle-id>/` | 用途 |
| --- | --- |
| `events.jsonl` | v3 追加事件，动态列表按成员及字段保存变化 |
| `objects/` | 提示词、代码、Skill、静态规格按内容哈希去重 |
| `meta.json`、`summary.md` | 可重建的索引与复盘摘要 |

相同观察不重复保存，常规变化合并采样，关键变化保留上下文。摘要不调用模型，不反复内嵌代码或几何边界。v1/v2 日志及旧转写继续兼容读取，不批量改写存量；缺失的旧信息不能补造。

反馈确认前同步正文和事件；损坏末行保留备份后修复，中间损坏明确报错。缺失引用、哈希不符和坏差量链不能静默跳过。精确编码、缓存和采样参数见 [battle-codec.ts](../../apps/companion/src/battle-codec.ts) 与 [battle-storage.ts](../../apps/companion/src/battle-storage.ts)。

## 历史与下载

历史页切换时读取最近十局，按开局时间排序，排除未进局记录和仍进行中的当前局；十局只限制显示，更早资料不删除。列表只读轻量索引，不加载全部脚本或观察。

单局 ZIP 包含完整逻辑事件、被引用正文、摘要与校验清单；命令、失败候选、修复和历次反馈均保留。导出无损转换并校验，不改原档；源在变化或损坏时明确失败。原 gzip 提交格式继续兼容，两者均可脱离游戏离线读取。

ZIP 在独立 worker 中准备并按流下载，避免阻塞对局；临时文件下载结束或过期后清理，源归档保留。下载使用原生浏览器文件行为。包不包含模型 Key、配置文件、认证头、浏览器资料、运行检查点、游戏素材或其他对局；用户自由输入的命令与备注属于归档正文。

读写与导出命令集中在 [AGENTS.md](../../AGENTS.md)。实现：[battle-records.ts](../../apps/companion/src/battle-records.ts)、[battle-export.ts](../../apps/companion/src/battle-export.ts)、[battle-downloads.ts](../../apps/companion/src/battle-downloads.ts)；HTTP 接口以 [workbench-api.ts](../../apps/companion/src/workbench-api.ts) 为准。
