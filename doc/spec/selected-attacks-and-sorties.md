# 现有单位攻击与飞机单次出击

`combat.attack` 可按 `selector`、`unitIds`、`quantity` 选择现有作战单位，`formationId` 可选。支持攻击已发现的敌人、敌方基地、单位、建筑或指定 `targetId`，`regionName` 限定真实异形分区。没有匹配目标时等待发现，不扩大地域或目标类别。

“所有飞机攻击敌方基地”选择当前飞机并建立攻击目标，不先建队、不追加生产。未编队成员使用全局脚本，已编队成员沿用对应编队脚本；选择混编队里的飞机不会指挥同队坦克。新命令生效时仍遵循每队脚本替换规则。原有 `combat.attack-all` 保留兼容，显式选择飞机或指定含飞机的队时也走同一出击流程。

玩家明确要求先编队再攻击时，攻击可绑定本句尚未完成交接的编队，等待实际成员归属。默认不会自动建队；绑定修正不得丢掉原来的编队、单位 ID、选择器、分区和目标范围，避免将一队飞机的失败操作改成全军进攻。

## 飞机状态

宿主从游戏快照读取每架飞机的 `ammo` 和武器 `cooldownTicks`，从本局规则读取该机型的弹药容量：

| 状态 | 行为 |
| --- | --- |
| pending | 弹药未知、未装满或尚未交接，等待，不发移动/攻击指令 |
| ready | 满弹且属于当前控制对象，可对匹配敌人下达攻击 |
| attacking | 游戏已接受攻击，等待实际发射，不逐步重发 |
| fired | 本次已接受攻击后，观察到弹药下降或武器进入新一轮冷却，该机本次任务完成 |
| lost/released | 成员损失或转交，不追加生产；全部结束时如实显示部分完成或失败 |

各机独立推进：已经满弹的先出击，其他飞机保持 pending。纯等待的命令侧栏显示“等待就绪”，同时给出逐机已投弹数量。每架实际发射一次即完成，不等目标掉血、摧毁、整轮弹药耗尽或返航。多发弹药机型首次发射也算本次完成。游戏继续处理后续飞行、返航及装弹；脚本不再次派出已完成飞机，不预判射程拒绝攻击。

目标完成不会停车，避免打断引擎中的返航。取消会撤销尚未完成成员的后续调度；已投弹成员不停车。投弹及已接受发令事实在宿主保存，随 v4 同局恢复，替换代码不清零。新的玩家攻击命令创建新的出击目标，重新按当时弹药状态决定等待或出击。

## 生成与验证

`prompts/capabilities/combat.attack.md` 声明参数，`prompts/tactics/attack.md` 说明生成逻辑。脚本每步读取宿主的 `attack.readyIds/targets`，不能把初次无弹写成永久结束。宿主限制 pending、出击中及已投弹成员的重复发令，并检查目标范围。生成阶段用隔离快照检查 pending → 满弹、装弹未满和已投弹阶段；等待装弹不触发无进展自动修复。

地面单位使用相同的现有成员和目标选择，按持续攻击任务运行。飞机规则不改变旧有地面守区、区域清敌或移动目标。
