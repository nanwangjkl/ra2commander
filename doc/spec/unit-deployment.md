# 常规单位部署

`unit.deploy` 将部署作为明确的目标姿态，由本机固定流程执行。适用于美国大兵（E1）、守卫大兵（GGI）、辐射工兵（DESO）、解放军（PLA）等具有 `Deployer` 规则且公开 API 提供 `isDeployed` 的单位；尤里类短时部署只施放本次技能，不持续维持。

## 命令与对象

- “2队部署”“2队解除部署”：原地调整该队可部署成员，混编中的其他单位保持归属，不参与姿态操作。
- “2队去二楼左下部署”：逐个成员移动到指定区域，再确认部署；移动到达不等于整句完成。
- “造两个辐射工兵，去二楼左下部署”：生产目标提供实际产物 ID，部署目标只接收这批产物，不需要创建临时编队。
- “造两个美国大兵编入2队，去二楼左下部署”：生产、原生集结和编队交接先完成，各成员随后独立移动部署。

能力参数见 [unit.deploy.md](../../prompts/capabilities/unit.deploy.md)。`source=auto` 优先关联同句匹配生产，`existing` 仅操作现有成员，`production` 仅接收同句明确的生产来源。关联保存生产目标 ID、兵种和数量，不接管之后同兵种的无关产物。没有匹配来源时反馈原因，不补造或虚构编队。

## 执行与完成

先遵守[生产集结点](factory-rally.md)的出厂放行，再等待已有编队交接。已经部署但需要赶路的成员先解除部署，然后移动，最后按目标姿态部署或保持站立；无目的地时原地执行。抵达要求进入目的地区域、接近落点，各成员独立推进。

动作携带明确的 `deployed=true/false`。宿主按快照判断，页面桥提交前再次读取公开状态，已达到要求时不重复切换。发令成功不等于完成，须观察到实际姿态。移动或姿态无进展时有限重试，耗尽后显示未完成原因；成员损失、转队或离开已交接编队也如实结束该成员。短时部署最多施放一次，未捕获状态时反馈未确认，不重复触发技能。

生产份额、已确认成员、交接及动作记录随 v4 状态保存，同局恢复不重造、不重放已确认切换。停止或取消后不继续部署；改令接管未编队成员时，其余成员及同批后续产物保留原任务。掩护待命不会自动移动已经部署的成员所在队伍。

基地车展开和建造厂收起、搬迁仍使用 `base.deploy/base.relocate`。本能力不接入灰熊变建筑的 Mod 变形，也不把运输卸载、建筑集结等其他 `canDeploy` 行为视作单位姿态。

## 实现入口

- `apps/companion/src/unit-deployment.ts`：现有选择及同句生产绑定。
- `apps/companion/src/deployment-plan.ts`：保留原话明确的部署要求，修正仅移动或虚构兵种编队的模型结果。
- `packages/runtime/src/goals/unit-deploy.ts`、`unit-deployment.ts`：固定执行、观察完成和持久化事实。
- `packages/game-werhd/src/bridge.js`：公开姿态采集、提交前幂等检查。

离线验证覆盖两条原始反馈、混编、生产集结与编队交接、短时部署、改令和同局恢复。本轮已获玩家实机认可并要求提交推送。
