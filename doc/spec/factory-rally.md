# 生产建筑集结点

对应[开发计划](../roadmap/factory-rally-and-exit.md)阶段 1 与反馈后的阶段 2，含静态障碍与四格到达修正，已于 2026-10-28 通过用户实机验收。

## 玩家入口

- “全部重工集结到三楼右下”：设置当前所有己方地面车辆工厂的后续出厂目的地。
- “盟军战车工厂集结到基地附近”：按现有建筑名称选择，目的地复用地图与基地参照解析。
- `cap production.rally {"unitIds":[123],"x":80,"y":60}`：只设置指定生产建筑。
- 没有位置依据的“这里”不编造坐标；重工、兵营采用附近默认候选并反馈实际坐标。船厂支持显式目的地，仍不自动设置默认位置。

能力声明为 `prompts/capabilities/production.rally.md`，与移动已经存在的未编队单位的 `management.rally` 分开。直接调用能力无需模型；自然语言通常一次理解，设置由本机直接提交，不生成脚本，不取消其他生产目标。

## 默认设置与覆盖顺序

本机接管一个车辆／步兵生产目标，或发现待处理的厂内成员后启用默认集结；已存在和此后新建的重工与兵营按建筑 ID 分别初始化。船厂、机场、建造厂不自动纳入；船厂在规则里也可能是 `Factory=UnitType`，须同时依据公开 `naval` 区分。兵营也在真实占地之外选择独立集结位置，不依赖某阵营兵营的默认内部出口坐标。

按 `art.ini` 真实 `Foundation` 和引擎车辆出口公式计算候选：占地原点加宽度是出口外侧，纵坐标加半个占地高度。当前 GAWEAP、NAWEAP 都是 5×3 格。默认候选距出口约 4～8 格，优先向外与两侧分散，避开已知建筑占地及边缘、其他出口、地面单位和已预留的集结位置。中心及周围八格均需无静态树石、位于有效地图范围，公开地形开阔、同高且与工厂同高；这些条件不能证明完整寻路可达。

每个采样轮最多处理两座，至少间隔 30 模拟 tick；已提交或回执未知的设置不周期重发。缺少可靠占地或附近没有候选时记录原因，默认失败最多尝试三次，每次至少间隔 150 tick，生产继续。缺少几何的建筑仍可显式指定坐标。

玩家设置覆盖默认设置；新造车命令不会重置它。公开 API 不能读回玩家鼠标设置，因此程序不保证识别鼠标改动，也不会周期覆盖它们。提交失败和回执未知分别保留，不把异常当成成功。

## 每次生产前复查

每个通过宿主提交的单位 `produce` 请求，在生产预留和实际调用之前复查对应类别的所有现有生产建筑；公开 API 没有当前主生产建筑标记，因此不凭最近一座或建筑顺序猜测。车辆对应地面重工、步兵对应兵营；已由本系统设置集结点的船厂按水面检查，未托管船厂保留原生设置，机场及建筑队列不套用地面规则。一批数量一次加入时，在该批提交前检查。

检查目标及周围 3×3 格的已知地形、高度和己方建筑真实占地，避开岩石、水面、墙、悬崖及建筑边缘；不因几个己方单位临时停留就反复换点。新建筑占住旧点时，自动位置在工厂附近重选；玩家指定的远处位置优先在旧点附近八格内重选，并保留已保存的分区边界。原玩家位置尚未探开而没有已知障碍时照常执行，不把未知当成已被占用；新候选仍要求公开已知的开阔地形。检查不能证明完整寻路可达。

冰天雪地额外加载 `maps/ice/static-obstacles.json`：由原始地图 `Terrain` 与 Format80 `OverlayPack` 导出 406 个初始阻挡格（357 个地形对象、49 个石块／墙覆盖物），约 4 KB，保存地图、规则及 art 来源哈希。树木占用位表示同格内的步兵子位置，不把树冠图片尺寸当成占地。运行时只读生成文件并校验地图来源，不访问原始资源、不追踪树石被摧毁。初始选点、显式指定、附近替换、生产前检查及出口让路统一检查 3×3；显式位置被挡时在附近选择开阔位置，黑幕不绕过静态障碍。

新进程加载／同局恢复也复查已有点一次，不等待下一批生产。旧点旁的树石使其失效时，设置与未就绪成员的改点同次保存、重置移动重试；已就绪成员不召回。暂时没有公开可用的新点时保留旧关联和原因，生产前可重查，不以四格容差放行仍去无效旧点的成员。

新点成功提交后才预占并提交生产。没有可用新点时保留本项目标和产量、显示等待原因，其他可执行生产继续；不额外追加生产，也不触发云端脚本修复去猜地形。检查途中改令、取消或换局使迟到结果失效；玩家同期修改了集结点时按新设置重查。

真实障碍导致换点时，尚未就绪并且仍去这个旧点的产物也改去新点，避免永远等待一块已被建筑占据的位置；已就绪成员不召回。普通玩家主动改点仍只影响后来出生者。这种障碍换点的准备状态与旧产物改点同次保存，同局重启不会将两者恢复成互相矛盾的目标。

## 动作、持久化和记录

桥使用独立 `setRallyPoint` 动作，复查同局、坐标、己方建筑与工厂类别，再调用公开 `werhd.order([id], {type: Move, target: {x,y}})`。引擎的建筑 Move 分支更新集结点，不给现有坦克发移动命令。默认选点查询位于 tick 回调之外；玩家改令、暂停／停止全局或换局使旧的自动结果失效。

设置完成表示指令成功提交，不表示能够读回设置，也不表示车辆已抵达。命令反馈明确为“集结点设置指令已提交”。同局检查点 v4 的可选 `factoryRallies` 保存建筑身份、原点、目的地、自动／玩家来源、关联命令、提交状态和尝试次数；先保存准备状态再发令。恢复时准备中改为回执未知，不自动重发覆盖后来的鼠标改动。无此字段的旧状态仍兼容。

建筑销毁、出售或换局后清理设置。v3 对局观察保存状态变化及相关 ID、目的地和失败原因，复用现有去重，不新增画面采集或额外报告。

## 出厂、到点与后续操作

根据用户实测反馈，坦克与步兵距离有效集结点不超过四格、位于生产建筑及出口周围两格通道之外，且空闲或至少约一秒模拟时间没有跨格位移，才释放给后续操作；正在接近或仍堵门均不放行。出生时保存对应建筑及当时设置的集结点，后来的设置不追溯修改这一批成员。产物身份与数量立即记账，但到点之前不编队、不发送交接停车、不执行攻击、掩护或上车组装；已到点的成员可以先交接，不等整批生产完毕。等待期间下达的新攻击命令保留为 pending，到点并完成原计划编队后执行。

公开 API 没有原生出生来源／集结点读回，因此结合首次出现位置、单位类别及真实建筑占地识别来源；无法确认时显示等待原因，不猜测到达或补造。可接住旧版本已经编队却仍卡在厂内的成员，保留已有归属并暂不让后续任务操作。矿车按公开规则识别，保留游戏原生采矿；空军与舰艇不套用此流程。

## 堵门与有限恢复

同一成员在厂内持续约三秒模拟时间没有位移，记录疑似出厂受阻。先找实际处于建筑或出口附近的可让路己方成员，分配不同的附近公开地形候选；正在采矿、维修、装卸、部署或近距离交战的成员不从旁路硬抢。让路期间统一暂缓该成员的其他动作，归属不变；抵达后只恢复仍有效的当前任务，改令、暂停／停止和换局使旧动作失效。

每座建筑最多三轮，每轮后观察位置变化再决定；没有可让路的己方阻挡者时，对厂内等待者有限尝试移向其集结点。前往集结点但停滞的成员也最多补发三次移动。回执成功不代表实际疏通，超过上限保留受阻原因和产物，其他任务继续，不擅自重造或宣称到点。游戏暂停不累计时间，Companion 重启重新建立进展计时。

前往集结点的三次重试耗尽后明确显示“集结受阻，重试已用尽”，不继续显示准备重试，也不按超时伪造就绪。

v4 检查点新增可选 `productionExits`，保存出生关联、集结目标、就绪状态、疏通尝试和临时让路关系；旧状态兼容，同局恢复不重复生产或盲目重放旧让路。归档按成员 ID 分别保存 `productionExits`、`factoryBlockages`、`exitYields` 变化，并补充己方类型、闲置状态与高度，便于复盘出口占用；不保存重复的整份新状态列表。
