# 维修车 Skill

第二个游戏 Skill 为 `repair-vehicle`，定义在 [`skills/repair-vehicle/SKILL.md`](../../skills/repair-vehicle/SKILL.md)。玩家于 2026-10-26 要求支持整套生产与组装、按坦克血量选目标、同队多车并行维修，并在实现后认可本轮效果、要求提交。

## 玩家命令

| 命令示例 | 行为 |
| --- | --- |
| 造维修车／造修理车 | 新造一个 IFV 和一名工程师，组装后持续维修己方受损坦克 |
| 造两辆维修车并编入1队 | 新造两个 IFV、两名工程师，进入1队，分别组装、并行维修 |
| 用已有组件组装维修车 | `memberSource=existing`，只用空闲现有组件，不额外生产；不足按可用部分执行 |
| 1队修理受损坦克 | `vehicle.repair`，使用该队现有维修车，不新增生产 |
| 维修队跟随2队维修 | 只指挥维修队，维修2队受损坦克，无伤员时跟随该队主体 |
| 所有维修车转入3队 | `formation.transfer`，`selector=repairVehicles`；仅选择实际载有工程师的 IFV |
| 取消维修车任务 | `skill.cancel`，停止本次 Skill 后续步骤，已入游戏队列的生产不回退 |

直接入口示例：

```text
cap skill.run {"skillId":"repair-vehicle"}
cap skill.run {"skillId":"repair-vehicle","quantity":2,"formationId":"1队"}
cap vehicle.repair {"formationId":"1队","followFormationId":"2队"}
cap skill.cancel {"skillId":"repair-vehicle"}
```

`quantity` 表示成品数量。默认 `memberSource=new`，明确“造”必须新造整套；`auto` 优先空闲组件和已组装维修车，再补缺项；`existing` 不补生产。没有指定编队时建立专用维修队；指定已有队会把新组件加入并替换该队脚本。其他编队脚本不受影响。

## 组成与执行

两类组件各展开为普通生产目标，沿用全局脚本、真实前置闭包、共享前置与生产记录。现有组件通过普通编队管理目标加入。后续组件入队使用动态 `management.kind`；同一步两个目标尝试建立同一队时，实际已建队后的动作改为转入。

组装和维修使用该队唯一的 `repair` 目标及脚本，提前编译后等待真实交接。宿主提供 `GoalView.repair`：`assembling` 为工程师与空载 IFV 的配对，`readyIds` 为确认载有工程师的车辆，`targets` 为逐车维修分工，`damaged` 为受损坦克实际血量，`follow` 为可选跟随点。脚本遍历全部配对及分工发令，不等待整批到齐；已组装车辆先开始工作。

上车动作使用公开 `werhd.order(..., EnterTransport)`。完成必须观察到工程师 ID 出现在载具 `transport.unitIds`。桥保留由公开 API 观察到的单位身份，供识别载员；运行时也持久化已知工程师 ID，换脚本或转队后继续按实际载员判断。载有其他兵种的 IFV 不作为维修车，不擅自卸载。

维修动作是 `repair(unitIds,targetId)` 桥原语，实际提交公开 API 的普通 `Attack`，发挥 IFV 工程师模式的负伤害武器。原生 `Repair` 用于工程师修建筑，不用于维修车；不使用强制攻击。宿主只检查目标仍为己方受损车辆，不设置距离或射程门禁，游戏负责接近及维修。

## 分工与状态

宿主读取完整己方快照，按当前游戏目录的坦克角色筛选 `0 < hitPoints < maxHitPoints`，排除敌人、矿车、满血及未知血量对象。默认全体己方坦克；指定 `targetId` 或被支援队后缩小范围。

每辆维修车独立工作，优先选择未被占用且较近的伤员，保留仍有效的独立分工。没有其他伤员时可以协修；出现新伤员时重新分开。目标修满、死亡或离开支援队时释放分工；成员失效不阻塞其他车。持续无移动、无回血时短暂避开该车与目标的组合，尝试其他目标。只给维修成员发令，不把坦克拉到维修车附近。

侧栏分别显示生产进度、已组装数量、组装配对数和当前维修分工。当前无伤员时保持持续待命，不能标成整项已完成。组件或车辆损失后不擅自补造；初始准备结束后无可工作或可组装成员时如实失败。指定支援队时，无伤员的维修车靠近该队主体，发现伤员即切换维修。

Skill 来源、版本、参数、组件目标、配对、已知工程师和维修分工保存在 v4 状态；同局重启不重放生产。取消或编队改令后停止原 Skill 后续步骤。暂停不累计维修停滞时间。

新能力、角色及政策仍从 Markdown 装配并参与提示版本；初次编译除常规干跑外，在隔离执行器内补查两车上车、两车分别维修阶段，避免准备期没有成员时空脚本误通过。检查不访问云模型或真实游戏；失败通过既有校验反馈交给模型修正。
