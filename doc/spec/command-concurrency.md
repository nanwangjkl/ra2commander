# 命令并发与下令顺序

用户于2026-10-28确认：独立语音／文本命令应并行理解，不能因下一句话到来而丢弃尚未理解完成的指令。

每条命令收到时登记独立的对局身份、顺序号和取消信号，立即开始自己的模型请求。模型可以乱序返回；普通命令按收到顺序绑定当前目标、单位和编队。后序已经理解但仍在等前序时，侧栏显示“等待前序指令”及理解摘要。绑定前重新读取当前目录与单位事实，提示词仍使用该命令捕获的完整版本。

目标绑定完成后即释放顺序位置，脚本生成和持续执行不占用普通绑定队列。生产等全局目标继续合并，同队行动仍由后下达的命令替换；不同编队相互独立。前序理解失败、取消或换局时释放等待位置，不使后续命令永久挂起。绑定失败的修正仍在本条绑定顺序内，已接受部分先生成执行，防止旧修正迟到后覆盖后令。

真实语音在录音开始时建立卡片，松开并接收完整音频时预留上述队列位置；本地识别完成后继续该位置和中止规则，不重新登记成更晚的新命令。识别失败、用户取消或换局时释放位置；停止全部可取消识别中的旧语音，范围停止仍只过滤其后来理解出的相关操作。详见[语音输入](speech-input.md)。

## 重复作战指令

重复下达同一句移动、守区或攻击命令表示重新执行，不能因已有相同活动目标而忽略。提示词明确要求返回能力调用；若模型仍返回空操作，宿主在轮到本条绑定后查找同局、同文、已接受且没有跳过部分的作战能力计划，将其作为意图模板重新校验、读取当前战况并绑定新目标。仅覆盖作战操作，不自动复制生产或其他资源操作；没有匹配模板时保留正常失败反馈，不复用其他原话或其他局的任务。归档记录 `repeatedFrom` 与模型原始空响应，便于区分理解与实际执行。读取归档本身不会执行任务，只有玩家新下达的这条命令才触发重绑定。

## 停止与取消

`control.stop/pause`、`goal.cancel`、`skill.cancel` 理解完成后优先处理，可以越过尚未返回的普通理解。CLI 直接控制使用相同的中止规则，不额外请求模型。

- 停止全部使更早的待处理命令失效；即使模型忽略取消信号，迟到结果也不能写入目标。停止之后新下达的命令正常登记。
- 停止单队或全局时，给更早请求标记相应范围。其模型返回后，只略过被中止的操作；同句中的无关建设或其他编队仍可绑定。
- 取消生产目标同时拦住更早请求中该项目的迟到追加；取消 Skill 拦住对应的迟到启动。已经存在的目标和实际游戏队列继续按原取消流程处理。
- 一句同时含优先控制和普通行动时，先处理控制部分，剩余普通行动继续等待其正常下令顺序。
- 每个异步绑定返回后重新检查对局和中止范围；停止、暂停及换局不会被旧流程恢复。编译回执继续使用控制对象修订和代次判断，不以模型返回顺序决定最后命令。
- 指定编队尚未创建时，也保存显式停止／暂停状态；稍后成员交接和掩护配置不能恢复行动，玩家随后明确的新命令仍可正常接管。

换局清理旧请求，归档读取不重放命令。队列和取消信号只存在于进程内；重启前未完成的理解不自动重新调用模型，按已有中断记录展示。

入口为 `transcript.ts`，顺序与中止范围在 `transcript-queue.ts`，能力分派在 `capabilities/index.ts`。模型适配器每次请求独立保存响应及用量，支持同一实例的并发调用。离线检查使用可控的乱序响应，验证建设累加、同队后令覆盖前令、优先停止、部分中止、失败释放及换局。
