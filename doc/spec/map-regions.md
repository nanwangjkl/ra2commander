# 地图分区

方案使用原生 `rx/ry` 格子坐标，可表达凹多边形、孔洞和多片区域，不要求矩形。地图版本与方案版本分开，同一地图允许多个作者、多套方案并存。当前数据为[冰天雪地 nanwang@0.1.0](../../maps/ice/schemes/nanwang-0.1.0.json)。

## 数据约定

- `map.id` 标识地图，地图 SHA-256 标识实际文件版本；`scheme.id/version` 标识作者方案。区域 ID 稳定，改名保留 ID，边界或名称修改更新方案版本。
- 边界为闭合环，坐标可为小数；标签点仅用于显示，不证明可达。“一楼”等 level 是命名分组，不直接等于地形高度。
- 名称与别名做统一归一化。常见“侧/边/方”等说法共用解析，精确名称与显式别名优先；仍有冲突时不任意吞并两个区域。
- 公共边界可同时属于多区，`regionsAt()` 返回全部，`regionAt()` 只在唯一归属时返回。地图文件的 Size/LocalSize 不等于 API 索引矩形。

图像提取、投影校准和来源哈希在 [import/annotations.json](../../maps/ice/import/annotations.json) 与方案中维护；不在文档复制整套数值。粉色线按线中部近似分界，不声称等于引擎障碍边缘。当前已做原生静态地形核对，方案中的实机校准标记保持原证据口径，不用日常功能验收伪造该标记。

## 有效范围与通行性

[playable-area.json](../../maps/ice/playable-area.json) 记录与地图哈希绑定的引擎有效格子范围，探索以它与分区的交集计覆盖及选点。图像外沿可能不在引擎范围内，但有效范围仍不证明步兵可达，水面、建筑和悬崖交给观察与寻路。

[static-obstacles.json](../../maps/ice/static-obstacles.json) 是生产集结使用的静态树石补丁。地图、站点边界规则或投影变化时重新导出核对。运行时仅依赖 JSON，不要求原生地图素材或标注图片。

## 提交新方案

在 `maps/<地图>/schemes/` 新增独立方案，填写地图哈希与方案身份，保留原有方案。图片导入需记录图片哈希、文字位置、投影与校准依据；其他剧场可直接提交原生坐标多边形，不必复用雪地图片工具。

提交时附边界叠加图与校准依据，运行地图校验及相关检查。结构校验和抽样不是任意多边形的完整拓扑证明。查询与离线工具命令见 [AGENTS.md](../../AGENTS.md)，读取器及工具在 [packages/maps/](../../packages/maps/)；类型定义与现有 JSON 是格式参考。
