# 建筑选址与间距

玩家于 2026-10-26 反馈“在基地上方、左边、下边各造一个巨炮”只落实了数量，要求补齐位置链路。方位约束只在命令明确提及方位时启用；另支持明确的分区内建造。未提位置的项目沿用默认自动选址。

## 建筑间距

玩家于 2026-10-30 要求所有新放置建筑遵守以下规则：

- 建筑与建筑的完整占地之间至少留一格，包含斜角方向，不能只比较建筑原点。
- 两座建筑都是防御建筑时可以紧贴；防御建筑与普通建筑之间仍须留一格。
- 任一侧是围墙时不增加间距限制。围墙、防御建筑仍须通过游戏自身的碰撞与放置检查。

页面桥在最终 `place` 入口统一筛选，因此自动选址、明确坐标、方位、分区以及必要前置建筑都遵守同一规则。检查己方、盟友和公开 API 当前可见的敌方建筑，不改变已有建筑的位置。防御建筑与围墙分别读取本局公开规则 `isBaseDefense`、`wall`，占地采用从 `art.ini` 导入的 `foundation`；当前目录的可建建筑均有占地数据，不通过名称猜尺寸。

同帧放置尚未出现在单位列表时，短期预留其占地，防止连续命令选择相邻位置。建筑实际出现后改用实时占地；卖掉、摧毁后空位可再次使用。游戏静默拒绝放置时预留会自动释放，不永久占位。缺少必要占地数据时保留就绪建筑并显示原因，不猜测一格尺寸。

没有同时满足间距、方向、分区和游戏规则的位置时，保留就绪建筑继续尝试，不取消重造，也不放宽玩家的位置要求。其他可执行目标继续推进。

本轮间距更新于 2026-10-30 由用户实机验收通过。离线验证覆盖完整占地、斜角间距、防御及围墙例外、自动与分区方位选址、同帧预留、拆除后空位复用和受阻重试；269 项测试及类型、提示词、游戏目录检查全部通过。

## 集结区避让

2026-10-30 后续胜局出现“5 辆坦克入队后，新电厂占用旧集结点”的时序问题。每次最终放置前，宿主收集当前生产建筑及未就绪产物所使用的集结点，页面桥优先选择不占用其周围 3×3 的落点。玩家指定的方位、分区、建筑间距及游戏 `canPlace` 仍须同时满足；围墙的间距豁免不豁免集结区检查。

只有避让搜索没有找到位置、仍有其他规则均合法的冲突落点时，页面桥返回候选坐标，不实际放置、不预占该位置。宿主将拟建建筑完整占地加入障碍，先重设受影响生产建筑的集结点，保留玩家原分区，并同步尚未就绪的成员；已就绪成员不召回。下一步确认待交接成员的改点移动均已提交后，才释放旧位置供建筑使用。单帧移动预算不足、暂停、回执未知或重试耗尽时旧位置继续受保护，同局恢复也保留此等待。没有开阔替代点时保留就绪建筑及原因，其他目标继续，不取消重造或调用模型猜位置。

手动或其他来源放置的建筑仍可能先占据旧点，因此建筑布局变化也触发集结点复查，不等待下次生产入队。具体状态与有限重试见[生产建筑集结点](factory-rally.md)。本轮待玩家实机验收。

## 命令与参数

`production.produce` 的可选位置参数：

| 参数 | 含义 |
| --- | --- |
| `placementDirections` | 画面方位数组：`up/down/left/right/up-left/up-right/down-left/down-right` |
| `placementAnchor` | 参照物，省略为基地；可指定现有己方建筑的角色/名称或已绑定分区 |
| `placementRegion` | 明确的分区内建造，使用真实异形边界，独立于方位 |
| `afterRelocation` | 明确要求搬迁后建造；同区建造也自动关联活动搬迁 |

“在基地上方，左边和下边各造一个巨炮，补3个电厂”对应：

```json
[
  { "capability": "production.produce", "params": { "target": "GTGCAN", "quantity": 3, "placementDirections": ["up", "left", "down"], "placementAnchor": "基地" } },
  { "capability": "production.produce", "params": { "target": "GAPOWR", "quantity": 3 } }
]
```

电厂和必要科技前置不继承巨炮的方向。没有方位的生产调用不生成 `placement`。一个方向可用于多座；数量多于方向数时按方向数组循环分配。列出多个方向但遗漏总量时至少保留每个方向一座。实际选择摘要包含各座方位及参照物，原话、结构化参数和目标随对局归档。

参照点在绑定时捕获，优先己方建造厂，展开前可使用基地车的位置；找不到指定建筑时选择现有基地参照并在摘要说明。分区使用其内部候选点。此约定不增加自动扩张基地、拆楼或撤回队列行为。

明确要求搬迁基地时，后续“基地”方位参照使用搬迁后位置；区域约束及执行依赖见[基地搬迁](base-relocation.md)。只要求“在一楼建造”时不添加方向，而是绑定 `placementRegion`；区域选址按边界与孔洞筛选，无合法格时不回退其他区域。

## 坐标与落点

上下左右按玩家看到的游戏画面解释。使用 RA2 等距投影的相对量：`screenX = rx - ry`，`screenY = (rx + ry) / 2 - elevation`，按八个扇区区分方位；不能直接以地图 y 减小表示屏幕上方。己方单位快照增加公开 API 的 `elevation`，选址时读取候选格地形高度。

生产目标保留整份逐座位置要求。每次目标生产提交将对应方位切片保存在 `ProductionRecord.placement`；前置与共享提交按实际归账目标捕获。当前就绪建筑的放置约束通过 `constraints.goals[id].placements[name]` 提供，宿主在执行器及最终提交前注入 `place` 动作。脚本若提出放置请求，仍只返回 `{kind:'place',name}`，不计算坐标，也不依靠临时 memory 轮换方向。

页面桥在参照点周围现有的 2～20 格搜索范围内，筛选要求方向，再调用游戏 `canPlace` 选择合法落点。尝试位置按本次生产记录及方位隔离；一座建筑的失败落点不影响下一座。找不到合法位置时保留就绪建筑，侧栏说明参照物和受阻方位；继续同方向尝试，其余可执行队列继续。该状态不让脚本跳过后续放置重试，也不改到其他方向。

## 完成与恢复

2026-10-30 胜局复盘发现，生成脚本因 `self` 中已有矿场而漏放新增矿场，靠自动修复才恢复，延迟约 23 秒。就绪建筑现由宿主按本次生产台账与真实 Ready 队列主动提出放置，先于脚本执行；已有同名建筑不抵消新增目标，脚本返回空动作也不漏放。旧脚本的 `place` 请求继续兼容，同步与共享前置按名称去重，共用预算、即时校验、间距及位置要求。

该子步骤仅服务于已生效且正在运行的生产目标，暂停、停止、取消、搬迁依赖和同局恢复继续遵守原生命周期。无合法落点时保留就绪建筑；编译检查不再要求脚本重复实现宿主已保证的放置动作，也不因只剩就绪建筑未落地就重编脚本。生产和交接等脚本步骤仍保留停滞修复。

发出放置不算完成。宿主观察新建筑真实出现后，记录其坐标、高度及方向是否符合本次提交要求。逐座实际确认后才推进下一个方位；同批排队多座也不能在第一座出现时把整条记录标成已放完。

全部新增数量及位置均满足才完成。数量已完成但实际位置不符时标为部分达成，保留未达标建筑 ID，不自动额外生产或拆除。没有位置要求时仍按原先的实际产出数量判定。

参照点、逐座方位、实际落点和匹配结果随 v4 目标与生产记录保存。同局重启、全局脚本替换与修复不重置下一座方向，不重播已提交生产。旧 v3/v4 无这些可选字段的记录继续沿用默认选址。

本轮离线验证覆盖原反馈的三方向与普通电厂、页面桥实际选址、方向无落点后的重试与其他目标继续、错误落点的部分达成、同批多座以及同局恢复。实机效果由玩家验收，不自动截图或移动镜头。
