# 建筑方位要求

玩家于 2026-10-26 反馈“在基地上方、左边、下边各造一个巨炮”只落实了数量，要求补齐位置链路。方位约束只在命令明确提及方位时启用；另支持明确的分区内建造。未提位置的项目沿用默认自动选址。

## 命令与参数

`production.produce` 的可选位置参数：

| 参数 | 含义 |
| --- | --- |
| `placementDirections` | 画面方位数组：`up/down/left/right/up-left/up-right/down-left/down-right` |
| `placementAnchor` | 参照物，省略为基地；可指定现有己方建筑的角色/名称或已绑定分区 |
| `placementRegion` | 明确的分区内建造，使用真实异形边界，独立于方位 |
| `afterRelocation` | 明确要求搬迁后建造；同区建造也自动关联活动搬迁 |

“在基地上方，左边和下边各造一个巨炮，补3个电厂”对应：

```json
[
  { "capability": "production.produce", "params": { "target": "GTGCAN", "quantity": 3, "placementDirections": ["up", "left", "down"], "placementAnchor": "基地" } },
  { "capability": "production.produce", "params": { "target": "GAPOWR", "quantity": 3 } }
]
```

电厂和必要科技前置不继承巨炮的方向。没有方位的生产调用不生成 `placement`。一个方向可用于多座；数量多于方向数时按方向数组循环分配。列出多个方向但遗漏总量时至少保留每个方向一座。实际选择摘要包含各座方位及参照物，原话、结构化参数和目标随对局归档。

参照点在绑定时捕获，优先己方建造厂，展开前可使用基地车的位置；找不到指定建筑时选择现有基地参照并在摘要说明。分区使用其内部候选点。此约定不增加自动扩张基地、拆楼或撤回队列行为。

明确要求搬迁基地时，后续“基地”方位参照使用搬迁后位置；区域约束及执行依赖见[基地搬迁](base-relocation.md)。只要求“在一楼建造”时不添加方向，而是绑定 `placementRegion`；区域选址按边界与孔洞筛选，无合法格时不回退其他区域。

## 坐标与落点

上下左右按玩家看到的游戏画面解释。使用 RA2 等距投影的相对量：`screenX = rx - ry`，`screenY = (rx + ry) / 2 - elevation`，按八个扇区区分方位；不能直接以地图 y 减小表示屏幕上方。己方单位快照增加公开 API 的 `elevation`，选址时读取候选格地形高度。

生产目标保留整份逐座位置要求。每次目标生产提交将对应方位切片保存在 `ProductionRecord.placement`；前置与共享提交按实际归账目标捕获。当前就绪建筑的放置约束通过 `constraints.goals[id].placements[name]` 提供，宿主在执行器及最终提交前注入 `place` 动作。模型仍只返回 `{kind:'place',name}`，不计算坐标，也不依靠临时 memory 轮换方向。

页面桥在参照点周围现有的 2～20 格搜索范围内，筛选要求方向，再调用游戏 `canPlace` 选择合法落点。尝试位置按本次生产记录及方位隔离；一座建筑的失败落点不影响下一座。找不到合法位置时保留就绪建筑，侧栏说明参照物和受阻方位；继续同方向尝试，其余可执行队列继续。该状态不让脚本跳过后续放置重试，也不改到其他方向。

## 完成与恢复

发出放置不算完成。宿主观察新建筑真实出现后，记录其坐标、高度及方向是否符合本次提交要求。逐座实际确认后才推进下一个方位；同批排队多座也不能在第一座出现时把整条记录标成已放完。

全部新增数量及位置均满足才完成。数量已完成但实际位置不符时标为部分达成，保留未达标建筑 ID，不自动额外生产或拆除。没有位置要求时仍按原先的实际产出数量判定。

参照点、逐座方位、实际落点和匹配结果随 v4 目标与生产记录保存。同局重启、全局脚本替换与修复不重置下一座方向，不重播已提交生产。旧 v3/v4 无这些可选字段的记录继续沿用默认选址。

本轮离线验证覆盖原反馈的三方向与普通电厂、页面桥实际选址、方向无落点后的重试与其他目标继续、错误落点的部分达成、同批多座以及同局恢复。实机效果由玩家验收，不自动截图或移动镜头。
