# 完整游戏目录与通用科技树

用户于 2026-10-26 要求统一解决尚未解锁的单位、建筑无法识别及其科技树依赖，避免逐项目手写配方。直接触发反馈为：在没有空指部时下令造巨炮，侧栏报“未找到可用生产项目：巨炮”；手动造出空指部后才认识巨炮。

## 数据来源

`pnpm game-data:import` 读取本地游戏站点的 `res/overlay/rules.ini`、`ra2.csf` 和 `art.ini`，输出 `prompts/games/catalogs/ra2web-gonghui.json`。当前导入 446 条类型记录，其中 439 条有实际规则定义，125 条科技等级非负；类型清单中的过时占位也保留标记，不能视为可生产项目。`art.ini` 仅提取建筑矩形 `Foundation` 占地，按规则 `Image` 或原生 ID 关联，用于集结点避让建筑和计算出口；自定义且无法解析的占地保持缺省，不猜测。数据不包含贴图、声音、地图对象位置或游戏存档。

目录保存原生 ID、类型、中文和英文名称、前置及覆盖前置、国家限制、科技等级、工厂类别和必要角色事实；同时导入 `POWER/PROC/BARRACKS/FACTORY/RADAR/TECH` 类别以及国家清单。数据版本由三个来源文件的 SHA-256 计算，记录来源文件名与哈希，导入不添加时间戳，结果可重复生成；未包含占地的旧目录仍兼容。

常规部署同时导入 `Deployer` 和 `UndeployDelay`，区分持续姿态与自动解除的短时技能；本局公开规则优先，公开 `isDeployed` 用于确认实际效果。`DeploysInto` 的建筑变形不自动纳入常规部署，灰熊变建筑的 Mod 能力按用户要求排除。详见[单位部署](unit-deployment.md)。

自动碾压导入 `Crusher` 和 `Crushable`，保留步兵默认可碾压、其他类型默认不可及执行能力默认关闭的规则。实际启用的三类车辆与狗的排除名单在 Markdown 中配置；公开 `rules()` 不提供这两个字段，静态能力不作为实际命中证明。详见[自动碾压](crushing.md)。

`current-mod.md` 的 `catalogFile` 选择这份数据。它与 Markdown 模板、角色、战术和 Skill 共同计算提示版本，加载错误保留上一套完整定义。Markdown 维护常用别名、角色与策略；完整建造依赖不按单位逐条维护。

## 本局规则优先

目录为发现尚未解锁项目及中文名称提供入口。所有实际候选仍通过公开 `werhd.rules(name,type)` 读取本局规则。类型、前置、价格、电力、科技等级与工厂信息按 API 返回值使用，地图覆盖的同名规则可以覆盖导入数据。

公开 API 没有完整规则枚举，因此由导入类型清单发现名称；批量读取每次最多 64 项，静态规则只在同一 `sessionKey` 内缓存，换局失效。当前可造性不缓存，每步使用最新 `production.available`。己方国家从公开 `me().country` 采集。

国家限制由导入目录提供提示；引擎确认当前可造时优先采用引擎结果，不被目录限制拦截。未知或不可造项目不能一律报“名字不存在”：明确国家限制、需要已有/展开的设施，以及前置已齐但引擎仍未开放生产，分别提供执行状态。地图额外引入、类型清单中尚不存在的新名称仍需重新导入相应 MOD 的目录或由当前可造清单发现。

## 目标理解

本地目录同时认识已解锁与未解锁的项目。中文名称、英文名称、原生 ID 与 Markdown 常用别名共用 `GameCatalog` 解析；`available=false` 只表示目前不可造。

“核电站／核电厂／核反应堆”统一使用 `nuclearPowerPlant`，按阵营选择 NANRCT 或 CANRCT，尚未解锁时沿用通用科技树补齐前置。它与泛称电厂 `powerPlant` 分开。绑定修正保留明确项目类别、数量、编队与位置，不把核电站降为普通 NAPOWR。防御建筑角色则采用本局规则 `isBaseDefense`，不把全部建筑归为防御设施。

模型请求按原话检索相关项目与角色候选，发送精简子集，不重复发送整份规则文件。原话没有明确匹配时使用有限候选兜底。模型只提交目标、数量、编队和明确的位置要求，不负责列出科技树。请求记录 `game.catalogVersion`，以便复盘当时使用的数据。

通用类别也由 `current-mod.md` 的角色规则声明：飞机、步兵、车辆、建筑按真实类型匹配，舰艇附加海军标记；允许只有 `match`、没有固定 `members` 的角色。模型候选检索和宿主生产绑定使用同一角色，复合命令按各类别保留候选，避免只识别电厂后把“造飞机”排除。候选带 `roles` 和国家限制，按实际可造性、适用国家和阵营排序；“造4个飞机”直接选择具体可生产机型，不需要每架飞机增加中文别名。类型大类不扩大明确兵种的替代范围，例如犀牛的阵营替代仍是坦克，不能选成任意车辆。规则禁止直接生产的附属飞机、导弹等不进入普通生产候选。

## 通用依赖规划

`computePrerequisiteClosure` 从目标递归查询前置，按依赖优先顺序输出。具体建筑名必须满足；类别项从当前类别成员中任选一个满足。已有设施优先，当前可造候选优先；其余候选按当前阵营排序，分支存在未知或不可满足条件时尝试后续候选，失败分支不会污染其他分支的结果。循环会被明确记录。

例如法国巨炮在只有建造厂时可自动规划电厂、矿场、空指部，最后生产巨炮；美国建实验室所需的雷达类别会选择适用美国的空指部变体，不误用禁止美国使用的候选。

科技前置外，单位类型还对应固有生产设施。宿主根据导入建筑的 `Factory` 和海军标记，统一推导建造厂、兵营、地面车辆工厂、船厂及飞机工厂候选；不为每一种单位写生产脚本。已有覆盖前置设施时复用其效果，仍检查生产设施；不擅自制造、占领中立科技建筑来满足覆盖条件。目标已被引擎确认可造时直接推进目标，不重复建设历史前置。

规划结果仍交给现有全局脚本执行。每步提供可造候选、剩余额度、已提交前置、就绪建筑及未满足条件，脚本按动态事实推进。多个目标的同名前置复用一份生产记录；明确要求新增的电厂等可以由共享前置提交归账。共享就绪建筑本步只放置一次。目标产量、提交确认、恢复不重播和每队/全局脚本架构保持原有机制。

原命令的方位要求仍只作用于目标建筑，不传播给必要前置。补齐前置后再按逐座方位放置，完成继续依据实际产出与真实位置。

## 检查与维护

`pnpm game-data:check` 校验完整目录，并针对各可选国家及相应生产项目计算依赖。当前为 381 个国家/项目组合，检查含固有生产设施、引用有效性与循环；不能代替实际地形、资金、引擎建造合法性及玩家验收。

离线关键验证重放本次中文巨炮命令：从只有基地、没有空指部的状态自动完成电厂、矿场、空指部与三座巨炮，并共用明确要求的电厂数量、保留各座方位。同时检查本局前置覆盖、国家候选、单位生产设施、失败分支及规则缓存换局失效。无自动截图、录屏或真实对局发令。
