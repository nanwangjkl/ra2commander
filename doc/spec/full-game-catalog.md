# 完整游戏目录与科技树

目录解决“尚未解锁就不认识”的问题，不按单位逐条编写建造配方。[导入工具](../../packages/command/src/import-game-data.ts) 从固定站点的 `rules.ini`、`ra2.csf` 和 `art.ini` 生成名称、类型、国家限制、前置类别、生产设施与建筑占地等事实；来源哈希决定数据版本，不添加生成时间戳。

[current-mod.md](../../prompts/games/current-mod.md) 选择目录并补充常用别名、角色与策略。类型大类可以按规则匹配，不要求为每架飞机列中文别名；具体兵种仍保留其范围。模型只接收与原话相关的候选，不接收整份规则文件。

## 实际规则优先

公开 API 不提供完整规则枚举，导入目录用于发现项目；实际候选仍读取本局 `rules()`，当前可造性逐快照更新。静态规则仅在同局缓存，换局失效。当前不可造与名字不存在必须区分，国家限制、缺设施和引擎未开放分别反馈。

必要前置递归计算，类别项选择当前阵营适用的设施，已有设施及已提交前置优先复用。单位的固有生产设施同样纳入；失败分支不能污染其他候选，不自行占领中立科技建筑。引擎已确认可造时直接推进目标，不重复补历史前置。

明确新增数量不被开局已有建筑抵扣。同名共享前置的新提交可归账给当时尚未完成的明确建设目标，避免再造一次。目标建筑的位置要求不传播给必要前置；实际产出、集结与放置仍按各自规范确认。

规则覆盖、目录占位或缺失数据都不能当作可生产证明。其他 MOD 引入的新类型需要重新导入或由当前可造清单发现。部署与碾压的静态字段也不能证明实际动作完成。

数据入口：[游戏目录](../../prompts/games/catalogs/)、[game-catalog.ts](../../apps/companion/src/game-catalog.ts)、[prepare-goals.ts](../../apps/companion/src/prepare-goals.ts)。导入与校验命令见 [AGENTS.md](../../AGENTS.md)。
