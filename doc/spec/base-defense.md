# 基地防守

“1队防守基地”“3队守卫基地附近”统一绑定 `combat.hold(defendBase=true)`：攻击所有进入基地车所在地图分区的可见敌人；没有区内敌人时原地待命。基地展开后以建造厂为锚点，使用完整异形分区，包括孔洞，不按部队位置画矩形。

## 选择与执行

- 优先选择己方基地车；没有基地车时选择离所选编队最近的己方建造厂。侧栏反馈实际基地与分区。
- 部队无需先到基地或分区中心集结，直接攻击区内与自身武器兼容的敌人。普通攻击不预判射程，由游戏负责接近和开火；已有掩护仍遵守协同行动及近身支援规则。
- 敌人离区后重新选择区内目标；没有区内目标则停止旧追击，停在当前位置，不自动回基地、巡逻或整理掩护站位。防守持续执行，暂时无敌不代表完成。
- 基地跨区后更新防区。展开、收起导致 ID 改变时，只接续原位置附近、符合真实部署关系的基地形态；基地消失后保留最后防区，不跳到远处另一座基地。
- 找不到基地或其位置未覆盖地图分区时明确反馈绑定失败，不改成守卫部队当前位置。原有显式分区／矩形守区入口保留。

## 生产、改令与恢复

编队仍有明确生产或交接时，防守要求保留并等待真实成员；不擅自补造或从现有单位凑数。新成员沿用出厂集结与停车交接，其他就绪成员先执行。

防守由本机固定流程执行，通常仅有一次命令理解请求。暂停、停止、改令、全灭和对局结束沿用普通编队规则；没有明确要求时不增加战损回撤。基地身份、最后位置和当前防区随 v4 检查点保存，同局恢复不重放命令。

能力入口为 `prompts/capabilities/combat.hold.md`，绑定在 `apps/companion/src/base-defense.ts`，运行逻辑在 `packages/runtime/src/base-defense.ts` 与 `goals/combat.ts`。验证覆盖真实冰天雪地分区、异形孔洞、离区停止、掩护待命、基地变形跨区、暂停恢复及待生产编队。
