# 命令重决策与脚本自动修复

目标是发现明确错误和有条件执行却长期没有进展的脚本，让当前模型根据游戏事实生成修正。正常逐步执行仍由本机脚本负责，不逐 tick 请求云模型。

## 名称与绑定

生产项目使用原生 ID、中文显示名或别名。原生 ID 在当前阵营候选中保留明确选择，阵营误选仍按角色选择本局候选；中文同名结合操作参数筛选：编队生产选择机动单位，带建筑方位的生产选择建筑。常用角色别名优先于自动导入的同名显示名，普通名称优先生产形态，避免将“灰熊坦克”绑定为部署后的 DMTK 建筑。

语音/模拟语音绑定失败时，先启用已绑定的部分，再发起一次有针对性的重新理解。模型收到原话、失败操作和原因、已经接受的调用、当前单位/编队/目标及相关目录候选；`prompts/templates/binding-repair.md` 要求按失败项下标返回修正。重试最多返回8个操作，已接受的相同调用去重，不重放整句话。复合 Skill 已部分提交时不重放整个 Skill；真实没有对象、数量不足等部分执行结果继续反馈。

修正仍走能力参数和宿主目标校验，使用本次命令固定的提示版本。攻击修正还由宿主保留原编队、选择器、单位 ID、分区与目标范围，不能将单队失败操作改成全军攻击。不支持的部分如实保留为未执行，不要求玩家确认同类候选。直接 CLI 能力调用不额外请求理解模型。

## 脚本生成与执行

生成阶段保留最多3次候选生成，逐次反馈语法、契约、隔离试跑、Skill、基地搬迁、采矿及飞机出击阶段检查错误。搬迁检查额外覆盖变形换 ID 后的移动和抵达后的展开。执行中连续3次错误后暂停故障脚本，自动请求修复。

额外的本机观察器按目标检查实际进展。当前无进展窗口和冷却均为900游戏 tick；游戏暂停、同 tick 重复采样不计时。观察生产提交/产出/队列进度、成员位置与归属、探索覆盖、组装载员及受损目标血量，重复发送或接受相同动作不视为实际进展。

只有存在可执行步骤时计时，例如可造且有资金、有队列空位，建筑已就绪，或有待移动、交接、组装、维修的成员。资金耗尽、队列占满/暂停、未决生产提交、等待前置/真实科技条件、等待交接，以及已确认没有合法建筑落点时暂停相应计时。飞机装弹等待和已接受攻击后的飞行等待不触发。待命维修和无具体行动目标的守区不触发。该机制检查脚本是否推进，不猜测引擎排队中的产物已丢失，也不释放未决额度。

停滞触发时旧脚本继续运行并生成候选，避免中断其他有效目标；候选通过检查后替换该控制对象整份脚本。异常暂停的脚本在修复失败后保持暂停，停滞诊断失败则保留旧脚本。每个对局/控制对象/目标修订最多自动修复两轮，新命令重置限额；更换代码本身不重置限额。

## 修复证据与状态

修复请求携带旧代码、当前分配给脚本的完整目标与剩余额度、最近最多20条动作/返回/异常，以及各目标可执行条件和无进展时间。单条动作列表和单位 ID 有上限；生成提示按当前受控成员、生产项目和维修对象选取相关单位，不只截取快照前5个。实际本机执行仍读取全量快照。

`repair.md` 和恢复战术要求保留目标、产量、地域、方位及实际进度。脚本内存可重建，生产记录、已交接归属和目标进度由宿主持有，不因换代码重放。停止、暂停、取消、新指令和换局继续通过编译租约及取消信号使迟到结果失效。

绑定修正请求/响应写入转写的 `bindingRepairs`，脚本修复证据及候选检查沿用现有对局归档。观察窗口和近期动作仅保存在当前进程内，重启重新观察，不重放历史行为。用户反馈只归档，仍由玩家与开发 Agent 复盘，不自动触发模型调用；没有截图或测试提示。

开发入口：`game-catalog.ts` 负责名称解析，`capabilities/index.ts` 和 `transcript.ts` 负责失败项重决策；`packages/runtime/src/recovery.ts` 负责本机观察，`ProgramController` 负责限次与脚本替换。

## 本机固定流程

阶段 5A 的新建筑维修、出售目标不进入脚本生成与停滞修复。固定处理器异常保留事实，在侧栏与归档显示“本机执行出错”，停止该目标后续发令，供开发修正；不请模型改写固定实现。同一控制对象其余目标继续，主动暂停/停止仍作用于整个对象。修正后用 `global resume` 清除本机错误，或取消目标。旧状态中无执行方式标记的建筑目标保持脚本执行及原有有限修复。
