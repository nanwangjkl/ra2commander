# 进攻时自动碾压

2026-10-30 用户批准自动碾压：执行车辆限定灰熊 `MTNK`、犀牛 `HTNK` 和苏军防空履带车 `HTK`；主动目标排除警犬。沿用攻击命令和当前控制对象，不单独调用 Skill 或增加模型决策。用户实测反馈碾压可以工作，随后授权修复剩余车辆停车及敌方名称绑定，并要求统一提交推送。开发计划见[自动碾压计划](../roadmap/crushing.md)。

## 规则和动作

现有目录导入 `Crusher` 和 `Crushable`：前者缺省为 false，后者仅步兵缺省为 true。启用车辆与目标排除名单维护在 `prompts/games/current-mod.md` 的 `crushing` 段；必须同时符合静态规则和名单。未导入这些字段的旧目录或未知车型保留普通攻击。配置随 Companion 启动读取，修改后重启生效。

目标必须是原命令允许的可见敌方地面步兵，双方桥面层相同。狗、磁爆步兵等不可碾压步兵、空中／水中目标继续普通火力；IFV、天启等未启用车型也沿用原行为。静态可碾压不证明实际可达或可击杀；地图规则覆盖、特殊姿态、寻路和碰撞仍由引擎处理。排除狗只约束主动配对，不能改变原生碰撞。

模型继续提交 `attack`，宿主在统一提交处转换符合条件的请求。内部 `crush` 携带车辆和敌人 ID，模型没有该动作权限。最终页面桥复查当前己方成员、敌人、地面／桥面状态和目标分区，使用当前敌人所在格提交：

```js
werhd.order([unitId], {
  type: 1, // OrderType.ForceMove
  target: { x: target.tile.rx, y: target.tile.ry, onBridge: !!target.onBridge },
})
```

ForceMove 不支持对象目标；也不混用普通移动或强制对象攻击。桥版本 24，升级在原页面重装，不刷新游戏。回执带实际落点，提交拒绝保持失败。

## 配对与掩护

普通编队、直接选中单位、区域进攻、守卫／防守及旧脚本的合法攻击使用同一个调度器。先筛选原指令的成员、敌方兵种、地域与就绪状态，再保留有效配对；未配对车辆按距离选择不同步兵。同格同桥面的目标共用一个接触点，活动目标之间共享占用。

碾压目标不足时，剩余车辆继续攻击原命令范围内的其他可攻击目标，例如载具、不可碾压步兵或建筑。复用普通攻击的目标分配和去重；集火要求共用稳定的火力主目标，明确分头攻击才独立选择。火力主目标独立于碾压配对保存，有效攻击令不会因本步未重发而被停车覆盖。没有其他合法目标时才待命或维持掩护；不能为填补空闲扩大敌方兵种、地域或空地范围，也不让剩余车辆挤向已占用的碾压目标。掩护车辆保持近身条件，对其他目标的火力支援仍采用 holdPosition 的最终射程复查。

静止目标不反复发令，目标换格后最多每 15 tick 刷新一次落点。原脚本本步没有新动作时，已确认配对仍继续追踪；新移动、停车或攻击其他类别的请求优先。目标消失、离区、飞起或失去资格时释放配对并结束旧强移，不据此记为击杀。

掩护队继续由现有预测协同器决定行军。最慢成员可以领行接近目标，其余主体只在领行者附近分头碾压；脱队和独立追赶的成员先遵守队形。掩护车辆只处理主体正在攻击且靠近主体的目标，目标逃远后回靠。HTK 的合法对空攻击优先于碾压；暂停、出厂未交接、让路及不属于当前控制对象的成员不能被旁路调度。

## 受阻、恢复与记录

以公开位置观察进展：累计移动一格即刷新进展时间，正常绕路不按“离敌距离未缩短”判为失败。三秒没有进展时重新提交强移，让引擎重新处理接近；订单拒绝也计入尝试，有限三轮后该配对改用普通攻击，并显示“碾压受阻，改用火力”。这一版采用重新提交目标格，不猜测相邻格一定能通行。

回退记录不在下一帧或脚本重编时清零。同一敌人确实移开至少两格后可重新尝试；玩家新指令使用新目标事实。暂停和同局恢复重置观察计时并复查实时目标，保留尝试及回退状态，不沿旧坐标盲发。停止、取消、改令、转编、战损及对局结束沿用原生命周期，迟到回执不能续发旧任务。出口临时让路后也交回协同器重新选敌，不重放旧强移。

每个作战目标的 `facts.crushing` 保存配对、最近目标格、位移进展、尝试次数、强移／火力阶段和最近实际回执（成功与否、提交数、失败原因）。现有命令卡片显示进展；v4 检查点和 v3 对局记录复用原有事实保存与去重，不新增 UI、截图或录屏。当前公开观察不能证明击杀归因，不将提交成功、到格或敌人消失记为“已碾死”。

离线验证入口：`tests/crushing.test.ts`、`tests/bridge.test.ts`。真实命中效果、不同桥面及队形流畅度由用户实机验收。
